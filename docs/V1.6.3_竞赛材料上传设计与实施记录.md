## 1. 数据模型与索引设计

### 1.1 新增集合：`competition_attachments`

- **云端集合权限（R2-2 部署时配置）**：`ADMINONLY`（仅云函数可读写，禁止客户端直接读写）。
- **文档 `_id`**：`deterministicId('competition_attachment', registrationId, clientRequestId)`，天然保证同一报名同一客户端请求标识幂等。

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 确定性 ID（`competition_attachment_<sha256前32位>`） |
| `competitionId` | string | 赛事 ID |
| `registrationId` | string | 关联报名意向 ID |
| `studentUserId` | string | 归属学生用户 ID（严格由云函数可信身份推导） |
| `cloudPath` | string | 云存储路径 |
| `fileId` | string | 云存储 `fileID` |
| `fileName` | string | 清洗后的原始文件名（去路径穿越、去控制字符、≤80 字符） |
| `extension` | string | 小写扩展名，白名单：`jpg` / `jpeg` / `png` / `pdf` |
| `contentType` | string | 服务端按扩展名映射的 MIME 类型 |
| `sizeBytes` | number | **服务端通过 `storage.statFile` 实测的文件字节数**（不采信客户端传值） |
| `status` | string | `active` \| `removed` |
| `createdAt` | Date | 创建时间 |
| `updatedAt` | Date | 更新时间 |
| `removedAt` | Date \| null | 删除时间 |
| `removedBy` | string | 删除操作者用户 ID |
| `uploadedBy` | string | 上传操作者用户 ID |
| `schemaVersion` | number | 固定 `1` |

### 1.2 索引设计（R2-2 云端创建）

| # | 索引名称 | 字段与方向 | 用途 |
|---|---|---|---|
| 1 | `idx_competition_attachments_competition_student_status` | `competitionId: 1, studentUserId: 1, status: 1` | 学生查询本赛事已上传材料、事务内计数上限校验 |
| 2 | `idx_competition_attachments_registration_status` | `registrationId: 1, status: 1` | 按报名记录聚合活跃材料 |
| 3 | `idx_competition_attachments_student_created` | `studentUserId: 1, createdAt: -1` | 学生侧按时间倒序排查与后续保留期清理 |

### 1.3 云存储路径约定

```text
competition-attachments/{competitionId}/{studentUserId}/{timestamp}-{random}.{ext}
```

- 服务端 `competition.register_material` 强制校验 `cloudPath` 必须以 `competition-attachments/{competitionId}/{可信actor._id}/` 开头，且后续为单一合法文件名（禁止 `/`、`\`、`..`、控制字符），扩展名必须与清洗后的 `fileName` 一致且在白名单内。

## 2. 六个云函数接口与权限矩阵

全部 6 个路由注册于 `cloudfunctions/api/actions/competitions.js` 并通过 `cloudfunctions/api/index.js` 装配（注入 `cloudfunctions/api/lib/storage.js`）：

| Action 路由 | 允许角色 | 数据范围校验 | 关键安全与业务行为 | 审计事件 |
|---|---|---|---|---|
| `competition.get_material_policy` | `student` | 仅可查本人所属训练组可见赛事的本人已上传数与剩余额度 | 返回扩展名白名单、10MB 上限、每人每赛事上限 3、已传数、剩余数；`studentUserId` 由可信身份推导 | 无（只读） |
| `competition.register_material` | `student` | 仅限本人有效报名且赛事为 `published` | 校验路径前缀、白名单扩展名、文件名清洗、服务端 `statFile` 实测大小（1B–10MB）、事务内上限 `< 3` 与 `clientRequestId` 幂等 | `competition.material.registered` |
| `competition.remove_material` | `student` | 仅可删 `studentUserId === actor._id` 的记录 | 重复删除幂等；先删云存储文件，若存储删除失败则显式报错 `STORAGE_DELETE_FAILED` 并保留 `active` 记录以便重试；成功后事务内标记 `removed` | `competition.material.removed` |
| `competition.list_my_materials` | `student` | 仅本人 + `status === 'active'` | 供学生报名页渲染材料列表与额度；已删除记录不返回 | 无（只读） |
| `competition.list_registration_materials` | `coach` / `developer` | 教练复用 `lib/management-scope.js`（`canFullyManageScope`）校验完整赛事管理范围；`developer` 全局 | 按 `registrationId` 分组返回活跃材料元数据，**不含永久下载链接或临时 URL** | 无（只读） |
| `competition.get_material_url` | `coach` / `developer` | 同上范围校验（`canFullyManageScope` / 全局） | 调用 `storage.getTempUrl(fileId, 60)` 生成 **60 秒** 有效临时链接；审计仅记录 `attachmentId` / `competitionId` / `registrationId`，**不记录 URL 明文** | `competition.material.downloaded` |

> **家长端隔离**：`parent` 角色调用以上 6 个接口一律返回 `FORBIDDEN`；材料元数据不进入任何排行榜、统计看板或 XLSX 导出。

## 3. 云存储封装设计（`cloudfunctions/api/lib/storage.js`）

仅暴露 3 个方法并支持依赖注入 `createStorage(cloudSdk)`（默认延迟加载 `wx-server-sdk`，测试注入内存假实现）：

1. `getTempUrl(fileId, maxAgeSeconds = 60)`：调用 `cloud.getTempFileURL`，状态非 0 或缺少 `tempFileURL` 时抛出 `STORAGE_TEMP_URL_FAILED`。
2. `deleteFile(fileId)`：调用 `cloud.deleteFile`，状态非 0 时抛出 `STORAGE_DELETE_FAILED`。
3. `statFile(fileId)`：调用 `cloud.downloadFile` 读取字节长度返回 `{ sizeBytes }`；捕获任何异常或空响应返回 `null`，供 `register_material` 拒绝未上传或超限文件。

## 4. 上传上限、幂等与数据留存策略

- **上传上限**：白名单 `['jpg', 'jpeg', 'png', 'pdf']`；单文件上限 `10MB`（`10485760` 字节）；每人每赛事活跃材料上限 `3` 份（在 `runTransaction` 内执行 `.where({ competitionId, studentUserId, status: 'active' }).limit(3).get()` 强校验）。
- **幂等机制**：基于 `deterministicId('competition_attachment', registrationId, clientRequestId)`；重复提交返回同一条记录且 `duplicate: true`，不重复写审计、不消耗配额。

  - 当前阶段未实现定时清理触发器；后续可在云函数定时触发器中按 `idx_competition_attachments_student_created` 或新增 `createdAt` 索引扫描超过 90 天的历史赛事附件，先删云存储文件再置清理状态并写审计日志。

## 7. 已知风险与验证边界

1. **10MB 文件 `statFile` 超时与内存风险**：当前 `storage.statFile` 通过 `cloud.downloadFile` 下载整文件计算 `byteLength`。在云函数当前 `timeout = 3` 秒（体检报告 `DEF-006`）且默认内存配置下，接近 10MB 的 PDF/图片存在触发 `TIME_LIMIT_EXCEEDED` 的风险；建议 R2-2 部署时调高 `api` 超时至 10–20 秒并实测 8–10MB 文件耗时。
2. **上传成功但登记失败的孤儿云文件**：若客户端 `wx.cloud.uploadFile` 成功但网络中断未到达 `competition.register_material`，云存储中可能残留未登记的孤儿文件，需结合 90 天清理任务或后续孤儿对账脚本回收。
3. **真实云存储与真机未验证**：本阶段仅完成本地内存假存储与单元测试验证；真实微信客户端 `wx.chooseMessageFile`、`wx.cloud.uploadFile`、`cloud.getTempFileURL`、`wx.downloadFile` + `wx.openDocument` 及跨角色真机隔离均留待 R2-2 部署后的 **阶段T综合验收**。
