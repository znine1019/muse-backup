# 阶段3｜训练计划与训练任务管理系统设计

**日期：2026-10-13**
**状态：本地代码与自动化测试完成；云端集合、索引与权限未创建，`api` 未重新部署。**

## 1. 产品目标

面向乔格体育俱乐部的教练与学生，提供完全人工制定的训练计划：

- 教练快速创建、编辑、发布、归档和复用训练计划。
- 学生按今日、本周和历史查看本人训练组已发布的训练计划。
- 训练计划只描述训练安排，**不等于考勤结果**，不记录学生实际到训情况。

## 2. 数据模型

### 2.1 新增集合 training_plans

为控制集合数量，计划头部与训练内容使用单集合并将训练内容嵌入 `items` 数组。

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` / `planId` | string | 确定性计划ID |
| `coachUserId` | string | 创建/负责教练用户ID |
| `trainingGroupId` | string | 所属训练组 |
| `title` | string | 计划名称，最长60字 |
| `startDate` | string | 开始日期，`YYYY-MM-DD` |
| `endDate` | string | 结束日期，`YYYY-MM-DD` |
| `status` | string | `draft` / `published` / `archived` |
| `version` | number | 乐观并发版本号，初始1 |
| `notes` | string | 计划注意事项，最长300字 |
| `copiedFromPlanId` | string | 复制来源计划ID |
| `items` | array | 训练内容数组 |
| `publishedAt` / `archivedAt` | date/null | 发布/归档时间 |
| `createdAt` / `updatedAt` | date | 创建与更新时间 |
| `schemaVersion` | number | 当前为1 |

### 2.2 训练内容 item

| 字段 | 类型 | 说明 |
|---|---|---|
| `itemId` | string | 计划内确定性内容ID |
| `order` | number | 训练顺序，计划内唯一 |
| `category` | string | 训练分类 |
| `name` | string | 训练名称，最长60字 |
| `eventCode` / `eventName` | string | 可选关联现有体育项目目录 |
| `target` | string | 训练目标 |
| `sets` | number/null | 组数 |
| `reps` | number/null | 每组次数 |
| `distanceMeters` | number/null | 距离（米） |
| `durationSeconds` | number/null | 持续时间（秒） |
| `restSeconds` | number/null | 组间休息（秒） |
| `load` | string | 负荷描述，例如 `70% 1RM` |
| `notes` | string | 该项注意事项 |

训练分类：`sprint`、`middle_long_distance`、`strength`、`jump`、`throw`、`recovery`、`technique`、`other`。分类与现有体育项目目录分离，但可通过 `eventCode` 关联项目，避免重复建立冲突标准。

## 3. 状态与复用

- `draft`：仅授权教练和 developer 可见，可编辑、可发布、可归档。
- `published`：训练组学生可见；教练可继续编辑（版本递增），也可归档。
- `archived`：保留历史，学生不再可见，不可编辑。

复制规则：

- 复制源计划生成新的 `draft`，`version=1`。
- 不继承发布/归档状态。
- 不修改源计划。
- 通过 `clientRequestId` 生成确定性副本ID，重复提交幂等。
- 训练组权限继续由服务端校验。

## 4. 接口设计

| 接口 | 角色 | 说明 |
|---|---|---|
| `plan.list_meta` | coach/developer | 返回训练分类、状态和可管理训练组 |
| `plan.list_manage` | coach/developer | 按状态、训练组和日期范围查询可管理计划 |
| `plan.get_manage_detail` | coach/developer | 查看计划详情 |
| `plan.create` | coach/developer | 创建草稿，确定性ID防重复 |
| `plan.update` | coach/developer | 编辑计划，必须携带 `expectedVersion` |
| `plan.publish` | coach/developer | 草稿发布，写入审计 |
| `plan.archive` | coach/developer | 归档计划，保留历史 |
| `plan.copy` | coach/developer | 复制为草稿 |
| `plan.list_student` | student | 查询今日/本周/历史已发布计划 |
| `plan.get_student` | student | 查看本人训练组已发布计划详情 |

## 5. 权限规则

- 学生只能查看本人有效训练组内 `published` 计划；草稿与归档不可见。
- 教练只能管理本人有有效 `group_memberships` 的训练组计划。
- developer 保留全局管理权限。
- 停用账号在业务逻辑前拒绝。
- 停用训练组不能创建、发布或复制计划。
- 客户端提交的 `role`、`openid`、`coachUserId`、训练组授权信息不参与服务端权限判断。

## 6. 并发与幂等

- 更新、发布、归档必须携带 `expectedVersion`；事务内重新读取并比较版本。
- 版本不一致返回 `PLAN_VERSION_CONFLICT`，不静默覆盖。
- 创建和复制使用 `clientRequestId` 生成确定性文档ID，重复提交返回已有计划。
- 创建、更新、发布、归档、复制在事务内同时写审计日志。
- `doc(id).set()` 的 `data` 不包含 `_id`。

## 7. 日期与时区

- 计划日期使用 `YYYY-MM-DD`，字符串比较即可完成范围查询。
- 服务端按中国时区 UTC+8 计算“今日”和“本周”（周一至周日）。
- 日期边界测试覆盖 `16:00Z` 跨日场景。

## 9. 前端页面

- `pages/coach-plan-list/coach-plan-list`：计划列表、状态筛选、查看内容、复制、发布、归档。
- `pages/coach-plan-edit/coach-plan-edit`：创建/编辑计划与训练内容，保存草稿，发布。
- `pages/student-plans/student-plans`：今日、本周、历史训练计划与详情。
- 学生首页、教练工作台和开发者工作台均提供训练计划入口。
