## 2. 前端配置位置

`miniprogram/config/env.js` 保存云环境和云函数名称：

```javascript
module.exports = Object.freeze({
  CLOUD_ENV_ID: 'cloud1-d8g0egkli3191959a',
  API_FUNCTION_NAME: 'api',
  HEALTH_FUNCTION_NAME: 'health_check'
});
```

不要把 AppSecret、云端 API 密钥或一次性开发者初始化码放入该文件。

## 3. 云函数环境要求

- `api` 和 `health_check` 必须部署到 `cloud1` 测试环境。
- `api` 需要临时配置 `BOOTSTRAP_ADMIN_CODE`，仅用于首次建立开发者账号；完成后必须删除并重新部署。
- `api` 必须同时配置 `BOOTSTRAP_ADMIN_OPENIDS`，只允许预先授权的服务端可信 OpenID 进入初始化流程。
- `system_config/bootstrap` 必须在部署前设置为 `developerInitialized: false`，作为初始化事务的并发控制点。
- 初始化必须同时满足 OpenID 白名单、一次性码和未完成状态；成功后永久关闭初始化入口。
- 其他云函数环境变量只存放非公开配置，不写入前端和 Git。
- 正式环境不得复用测试环境的数据库或初始化状态。

## 4. 云开发配置边界

- 只使用微信开发者工具内的“微信云开发”，不要混用独立腾讯云 CloudBase + JS SDK 的认证流程。
- 前端只调用云函数，不直接读写 `users`、`student_profiles`、`role_bindings` 等业务集合。
- 身份依据必须由云函数从可信上下文取得，不能信任前端提交的 `openid`、`role` 或 `studentId`。
- 教练员的数据范围由 `group_memberships` 在服务端计算，前端选择或伪造训练组 ID 不能扩大权限。
- 学生接口不接受目标学生 ID，只返回当前可信身份对应的数据。
- 角色选择和页面跳转只用于界面展示，所有敏感 action 必须在云函数重新校验。

## 5. 人工完成后反馈的信息

只反馈以下非密钥信息：

1. `health_check` 是否显示云函数与数据库连接正常。
2. `api` 和 `health_check` 是否部署成功。
3. `BOOTSTRAP_ADMIN_CODE` 是否已配置，以及首位开发者是否初始化成功。
4. 数据库集合、索引和权限是否按清单创建。
5. 模拟学生注册、教练审核、角色切换和越权拒绝结果。
6. 开发者工具控制台中的完整错误文本（如有）。
