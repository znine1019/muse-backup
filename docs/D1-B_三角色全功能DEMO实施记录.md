## 4. 已保留的业务规则

1. **家长授权隔离**：待核验关联不返回概览与六类受保护数据，受保护模块 `restricted`；
2. **学生未发布计划不可见**：`visiblePlansForStudent()` 只返回 `published` 且属于本人训练组；
3. **未审核成绩不入正式数据**：`personalBests()` / `performanceLeaderboard()` 只使用 `approved`；
4. **教练范围隔离**：`studentsOfCoach()` / `coachTodos()` 只覆盖本人授权训练组；
5. **教练内部评价不向家长展示**。

## 9. 补充：三角色**页面**数据联动（本轮修复）

### 9.1 修复的问题
D1-B 主体只把联动做在数据源层：`student-demo.js` 与 `parent-demo.js` 仍渲染各自的静态示例，体验人员看不到教练操作产生的变化。本轮把这两个模块**改为统一数据源的视图适配层**。

### 9.2 实现方式
- `student-demo.js`：演示学生映射为统一数据源的林越（`stu_lin`）。计划、考勤、成绩、正式 PB、排行榜、通知、反馈、赛事意向、个人档案全部**实时从数据源派生**；`ALL_PLANS` / `NOTICES` 改用 getter，保证调用方每次拿到的都是当前状态。
- `parent-demo.js`：家长映射为 `parent_lin`，学生列表来自预置关联（林越已生效 / 苏晴待核验）；成绩、计划、考勤、反馈、赛事、通知全部从数据源派生，并**严格保留字段白名单**（不返回 `coachComment`、不返回请假原因、不返回精确位置）。
- **家长详情授权校验（新增）**：`getParentNotice` / `getParentCompetition` 在返回前校验“该内容是否落在家长已生效授权的训练组/学生范围内”。未授权时抛出 `DEMO_NOT_AUTHORIZED`，页面只展示“无权查看该详情”，不渲染任何数据；因此**直接 URL 或切换学生后使用旧详情 ID 都无法读取未授权学生的数据**。
- 页面新增 `restrictedDetail` 状态；学生端模拟写入（签到 / 提交成绩 / 提交反馈 / 提交意向）通过 `submitKind` 写入统一数据源。
- 新增仅面向四项组的 `notice_3`（用于验证家长未授权详情拦截），并为林越补充一条待批请假，使“教练批准 → 学生页面显示已批准请假”可在页面上直接验证。

### 9.3 页面级联动结果（均已自动化验证）

| 操作 | 页面结果 |
|---|---|
| 教练发布草稿计划 | 重新进入学生端，计划概览与计划模块出现该计划；未被发布的草稿仍不可见 |
| 教练通过成绩 | 学生端 PB 更新、成绩模块显示“已通过”、排行榜同步；家长端成绩同步更新 |
| 教练驳回成绩 | 学生 PB 不变 |
| 教练批准请假 | 学生考勤显示“已批准请假”；家长端显示签到状态但**不含请假原因** |
| 教练发布通知 | 学生端通知列表新增该条且可打开详情 |
| 未授权详情 ID 直接打开 | 家长端进入“无权查看该详情”，不渲染数据 |

### 9.4 新增测试
`tests/demo/page-linkage.test.js`（**9 项**）：真实加载 `pages/demo/demo.js` 并按角色渲染，断言 `instance.data.*`（即 WXML 直接绑定的字段）——发布计划→学生页面出现、通过成绩→学生 PB + 排行榜 + 家长成绩、驳回不变、批准请假→学生与家长状态一致且无原因泄漏、发布通知→学生页面新增、未授权详情 ID 被拒、切换学生后旧 ID 仍受约束、三角色渲染与操作**零云端调用**、既有通知详情与家长快捷导航未受损。

## 10. BUG-05：退出导航回正式工作台（P0 修复）

### 10.1 问题

学生端 DEMO 底部仍保留“退出演示，返回开发者工作台”。点击后 `reLaunch` 到正式 `pages/admin/admin`，并可从正式工作台继续进入学生、教练员、家长工作台，触发 `DEMO_BUILD_BLOCKED` 页面错误。

### 10.2 修复

1. 删除 `goAdmin()`，新增 `goDemoHome()`：清理演示状态与当前模拟身份后，使用 `wx.reLaunch('/pages/showcase/showcase')` 清空导航栈。
2. 拒绝进入与退出按钮统一回到 DEMO 首页，不再读取 `demoDestination` 中的正式工作台路由。
3. DEMO 模拟会话改为 `roles: []`，仅记录 `demoRole`；正式页面无法通过角色校验。
4. `getSessionDestination()` 在 DEMO 构建下对模拟会话与缺失会话统一返回 `pages/showcase/showcase`；真实正式会话的原有路由逻辑保持不变。
5. 未选择体验身份时，`app.ensureSession()` 返回无角色的 DEMO 访客会话；直接打开正式路由也会被页面角色守卫送回 DEMO 首页。
6. 清理 DEMO 页“仅对真实开发者开放/返回开发者工作台”等旧文案与注释。
7. 修正教练员 DEMO 目录导出名不一致（`COACH_CATALOG`），避免教练员入口因目录为空而渲染失败。

### 10.3 导航闭环

- DEMO 首页 → `/pages/demo/demo?role=student|coach|parent`
- 页内模块 / 目录 / 工作台 / 详情 / 返回 → 仅 `/pages/demo/demo`（详情优先 `navigateBack`）
- 退出模拟身份 → `wx.reLaunch('/pages/showcase/showcase')`
