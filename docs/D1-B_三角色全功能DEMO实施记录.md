## 2. 统一虚构数据源

- **三个模拟训练组**：中长跑队、四项组、专项组；
- **两名模拟教练**：林教练（专项组 + 中长跑队）、苏教练（四项组 + 中长跑队）——**预置带队授权，不依赖任何审批流程**；

## 3. 教练员端模拟业务

新增 `miniprogram/demo/coach-demo.js`，并在共用演示页 `pages/demo/demo` 增加 `role=coach` 分支：

- **工作台**：教练切换（预置授权）、今日训练与考勤（应到/已签/待签）、待办（待批请假 / 待审成绩 / 待评价反馈）、赛事意向、学生名册（含 PB 与待审计数）、全部功能入口；
- **全部功能目录**：训练计划、考勤管理、请假审批、成绩审核、学生名册、排行榜、训练反馈、赛事管理、通知发布；
- **详情 + 模拟操作**：每个可点击条目都有真实交互——
  - 计划详情 → **模拟发布**（发布后学生端立即可见）
  - 请假详情 → **模拟批准 / 驳回**（批准后学生考勤变为"已批准请假"）
  - 成绩详情 → **模拟通过 / 驳回**（通过后才进入正式 PB 与排行榜）
  - 反馈详情 → **模拟补充教练评价**（家长端仍看不到内部评价）
  - 赛事意向详情 → **模拟标记已代报**
  - 通知模块 → **模拟发布通知**（写入本地数据源，学生端通知列表出现该条）

## 4. 已保留的业务规则

1. **家长授权隔离**：待核验关联不返回概览与六类受保护数据，受保护模块 `restricted`；
2. **学生未发布计划不可见**：`visiblePlansForStudent()` 只返回 `published` 且属于本人训练组；
3. **未审核成绩不入正式数据**：`personalBests()` / `performanceLeaderboard()` 只使用 `approved`；
4. **教练范围隔离**：`studentsOfCoach()` / `coachTodos()` 只覆盖本人授权训练组；
5. **教练内部评价不向家长展示**。

## 5. 云端零调用隔离（沿用 D1-A 三层）

1. `app.js` 在 DEMO 构建下**不初始化云开发**；
2. `services/api.js` 在触碰 `wx.cloud` 之前抛出 `DEMO_BUILD_BLOCKED`；
3. `ensureSession()` 返回本地模拟会话，不经过正式登录，也不需要真实角色。

本轮的模拟写入**只作用于内存数据源**，测试用 `wx.cloud` 探针证明全程 **0 次 `init`、0 次 `callFunction`**。
