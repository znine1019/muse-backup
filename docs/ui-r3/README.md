## 一、三套方案定位、适用角色与信息架构核心差异

被替换基线为当前 F1 / `jg-` 视觉体系（`miniprogram/app.wxss` 中深蓝 `#103A6B` + 竞技青 `#00A7C4` + 能量橙 `#F2711C`、传统圆角卡片 + 顶部页头）。R3 三套提案在**信息架构（IA）与页面布局范式**上给出三条实质不同的演进方向，而非仅更换配色或圆角：

| 对比维度 | V1 赛场指令（Field Command） | V2 数据账本（Editorial Ledger） | V3 分栏任务流（Task Rail） |
| --- | --- | --- | --- |
| **核心定位** | 户外田径场单手高频执行面板 | 瑞士排版细线高密度台账 | 面向审批、录入与多角色治理的工作流任务轨 |
| **最适用角色** | 学生（高频签到/看当日安排）、现场执教的教练 | 教练（榜单与批量审批）、开发者（运维巡检）、家长（纵向查档） | 全四角色均衡覆盖（学生/教练/家长只读/开发者） |
| **首屏信息架构** | 单焦点碳黑指令卡（强聚焦 1 个核心数字）+ 双列快捷入口面板 | 无深色大卡；直接呈现编号分带（`01/02/03`）+ 三列等宽指标条 + 表头明细行 | 顶部三段式业务流程轨（`STEP 1 → 2 → 3`）+ 按优先级分色的左侧 5px 语义任务轨 |
| **导航与动作分区** | **底栏导航 + 内容内嵌按钮**：底部双排固定 7 屏导航，主按钮随页面滚动 | **顶栏索引 + 零底栏**：顶部双排全宽细线索引，底部完全释放给表格与表单 | **顶栏切换工作区 + 底部单排上下文主操作坞**：导航在顶部，当前屏主操作固定在拇指区 |
| **长表单与多分区策略** | 独立卡片包裹折叠区，需与双排底栏争抢纵向视口 | 全宽无边距账本抽屉折叠，纵向视野最大但提交键随页滚动 | 渐进式折叠任务轨 + 底部固定主操作坞（如“+ 新增条目 / 保存计划”） |
| **只读/边界表达方式** | 顶部浅绿提示条 + 复用碳黑 Hero 卡 | 细线只读批注带 + 纯查询账本表 | 左侧钢蓝只读轨 + 底部操作坞锁定为“只读守护模式 · 无写操作” |

### 严格遵循的产品事实约束

三套方案全部对齐 `docs/乔格体育_开发需求说明书_V1.6.md` 与现网 36 页事实：
1. 四角色：学生、教练、家长（严格只读，不暴露精确 GPS 坐标与教练内部评价）、开发者。
2. **不包含**签退、请假附件、AI 训练计划生成、第三方体测仪器对接、付费功能。
3. 竞赛报名明确区分“内部意向与材料审核”与“外部官方渠道报名成功”。
4. 考勤榜单明确呈现“历史成员不完整估算口径（`rank` 置空）与样本不足 3 场不领先”提示。
5. 全部样式仅采用微信小程序原生兼容子集（`display: flex`、定位、`transform`、`linear-gradient`），**零** `CSS Grid`、**零** `backdrop-filter`、**零** `filter`、**零** `position: sticky`、**零** 外部字体或 CDN、**零** 地图/图表第三方 SDK。

## 三、明确推荐方案、理由与代价

### 推荐选择：**V3 分栏任务流（41 / 45）**

**核心推荐理由：**
1. **最匹配乔格训迹的真实业务结构**：本系统是 300 人内部训练与审核管理系统（36 页中包含大量审批队列、计划多条目表单、考勤创建、赛事材料核验及严格的四角色权限隔离），而非单一消费级运动打卡 App。V3 通过“顶部流程轨 + 左侧 5px 优先级色轨 + 渐进折叠 + 底部单排主操作坞”，让四类角色在同一套规则下各得其所。
2. **表单与高频动作兼得**：教练编排训练计划（多条目增删）和创建考勤场次时，主操作固定在底部单排操作坞，比 V1 的双排底栏少占约 46px 纵向高度，又比 V2 的无底栏减少反复回滚找提交按钮的摩擦。
3. **只读边界与高风险提示最强**：家长工作台通过钢蓝信息轨 + 底部“只读守护模式”显式锁死写操作预期；教练/开发者高优先待办与“内部审核 ≠ 官方报名”用陶土红左轨 + 显式徽章双重提示，降低误操作率。

**选择 V3 必须接受的代价：**
1. **底部操作坞的端侧适配工作量**：在 R4 落地小程序时，需要为底部固定操作坞统一封装 `safe-area-inset-bottom` 安全区和键盘弹起避让逻辑（在 `input`/`textarea` 聚焦时隐藏或下沉，避免在 iOS/Android 微信端遮挡输入框）。
2. **数据报表密度略逊于 V2**：统计排行榜与开发者巡检页的同屏记录数比 V2 少约 15%–20%，R4 落地时可在统计/列表类页面适当收紧任务块内边距以吸收 V2 的表格可读性优势。
3. **首屏视觉张力比 V1 克制**：学生首页没有 V1 的碳黑大数字 Hero 冲击感，更偏冷静专业工具气质。

## 四、三套方案各自的「不建议采用的理由」

### 为什么可能不采用 V1（赛场指令）
- **双排底栏与长表单/审批页冲突**：训练计划编辑、考勤建场次、赛事材料上传等页面输入项多，固定底栏与碳黑大 Hero 会明显压缩有效编辑视口。
- **四角色适配失衡**：碳黑指令卡在学生/教练首页很出彩，但套用在开发者控制台、家长严格只读页时视觉重量过重，容易产生“仪表盘外壳套普通表单”的割裂感。
- **高密度对照弱于 V2**：成绩榜、考勤估算提示、多条审核队列在卡片圆角与大留白下需要更多次翻屏。

### 为什么可能不采用 V2（数据账本）
- **单手拇指区操作成本高**：无底栏设计虽换来极高内容密度，但在操场边单手使用手机时，反复伸向屏幕顶部切换导航或回到列表底部找按钮效率明显低于 V1/V3。
- **情绪温度偏理性冷峻**：纯锐角细线账本风格非常适合教练/开发者/家长查数，但对日常使用的青少年学生群体略显严肃、像财务/统计表单。
- **全站改造工作面略偏重**：现网 36 页大多基于圆角卡片与 `jg-card` 容器，全面改为无圆角全宽细线分带需要逐页核查边框重叠与窄屏列宽对齐。

### 为什么可能不采用 V3（分栏任务流）
- **底部操作坞需谨慎治理键盘与原生 tabBar 叠加**：微信小程序若在 tabBar 页面叠加固定操作坞，容易出现“双底栏”拥挤感；R4 必须严格约定：tabBar 页不挂操作坞、仅二级表单/详情/审批页启用操作坞。
- **顶部工作流轨（3-Step）在纯浏览页可能显得多余**：并非所有 36 页都有明确三步流程，若强行每页都塞三段进度条会造成视觉冗余；R4 需将其设为 `<jg-page-head>` 的可选插槽，仅在流程型页面展示。
- **在纯榜单对比场景不如 V2 紧凑**：面对 30+ 人的完整训练组考勤/成绩榜单，左轨卡片的边框与间距仍比 V2 纯细线表多占约 15% 纵向空间。
