# F1 融合设计系统与交互规范｜乔格训迹 V1.6 阶段7

**项目**：乔格训迹系统 V1.6
**原型路径**：`docs/ui-phase7/F1-融合终版/index.html`
**日期**：2026-10-13
**状态**：融合方案已定稿为原型，**尚未修改任何正式小程序页面**；本轮只新增 `docs/ui-phase7/` 内容

> 本规范是阶段7全站实施的唯一视觉与交互依据。所有数值均可直接换算为小程序 `rpx` 并在 `app.wxss` 中落地。

## 1. 设计理念

**一句话**：用 A3 的骨架装 A1 的数据，用 A2 的情绪照顾学生。

三条原则：

1. **信息优先**：页面先回答"现在要做什么"，其次才是"还能做什么"。任何装饰不得挤占首屏业务信息。
2. **数据即主角**：关键运动数值（PB、出勤率、排名、成绩）用大号等宽数字与深蓝数据卡承载；其余信息保持克制，不与数值争夺注意力。
3. **统一而不均质**：全站共享一套颜色、字体、间距、组件与交互反馈；三个角色只在**信息分组与首屏优先级**上不同，不出现三套不兼容的视觉体系。

设计尺度：**浅色底 + 深蓝品牌 + 高对比文字 + 限量竞技强调色**。深色仅用于数据卡，不用于全站背景。

## 2. A1 / A2 / A3 融合规则

| 来源 | 负责范围 | 落地规则 | 明确不允许 |
|---|---|---|---|
| **A3 极简专业数据** | 全站信息架构、工作台结构、列表 / 表格、筛选、表单字段组、导航 | 左右字段组（标签在左值在右）、行内操作、少量卡片、按职责分组的入口列表、紧凑但不拥挤的节奏 | 不允许沿用 A3 的 11—12.5px 正文与 38px 触控目标（本轮已提升到 14px / 44px） |
| **A1 竞技科技** | 关键运动数据、图表、排行榜、系统状态 | 深蓝数据卡承载核心数值；等宽大号数字；竞技青作为图表与高亮色；能量橙用于"当前/最优"标记；精细边框线作为科技感装饰 | 不允许全站深色背景；不允许切角、发光等高成本装饰进入表单与列表 |
| **A2 现代运动品牌** | 学生首页、今日训练、目标进度、训练完成与进步提示 | 亲和力卡片、明确的主要操作按钮、进度条与进度表现、必要时的领奖台（仅前三名） | 不允许大面积橙色铺满全站；不允许为了视觉吸引力降低信息密度 |

**角色差异边界**：三个角色共用同一套令牌与组件库；差异只体现在**首页分区顺序、分区数量与首屏重点**（见第 13 节）。

## 4. 字体层级

### 4.1 字号体系（px ↔ rpx，按 750rpx 设计宽度换算）

| 级别 | 令牌 | 字号 | 换算 rpx | 用途 |
|---|---|---|---|---|
| 显示数值 | `--fs-display` | 34px | 66rpx | PB、核心指标（数据卡内） |
| 大数值 | `--fs-num-lg` | 26px | 50rpx | 次级数值、排行榜成绩 |
| 指标数值 | `--fs-num` | 20px | 39rpx | 指标卡、列表右侧数值 |
| 页面标题 | `--fs-h1` | 22px | 42rpx | 页面主标题 |
| 区块标题 | `--fs-h2` | 17px | 33rpx | 页面分区标题 |
| 列表主文 | `--fs-h3` | 15px | 29rpx | 卡片标题、区块头 |
| **正文** | `--fs-body` | **14px** | **27rpx** | 列表主文、按钮、输入值（可读下限） |
| 紧凑正文 | `--fs-body-s` | 13px | 25rpx | 表格、标签页、行内按钮 |
| 次要说明 | `--fs-sub` | 12.5px | 24rpx | 时间、范围、状态说明 |
| 微标签 | `--fs-cap` | 11.5px | 22rpx | 单位、角标（仅限短文本） |

**硬规则**：正文不得小于 14px / 27rpx；`--fs-cap` 不得用于句子级文本；不通过缩小字号换取信息密度。

### 4.2 行高与字重

| 场景 | 行高 | 字重 |
|---|---|---|
| 标题 | 1.30 | 700 |
| 正文与列表 | 1.55 | 600—700（列表主文 700） |
| 说明文字 | 1.55—1.60 | 400—600 |
| 数值 | 1.0—1.1 | 800 |

### 4.3 数字字体规范

- 所有数值使用 `font-variant-numeric: tabular-nums`（小程序：`font-feature-settings: 'tnum'`）并统一等宽字体族：
  `font-family: "DIN Alternate","Bahnschrift","SF Mono",Consolas,monospace;`
- 数值与单位分离：数值用数字字体，单位用 `--fs-sub`/`--fs-cap` 的正文字体，单位常驻显示（不依赖占位符）。
- 同列数值右对齐，保证纵向可比。
- 百分比、时间（`16:00`）、坐标（`30.65820, 104.06530`）同样使用等宽数字。

## 7. 数据卡片规范

**深蓝竞技数据卡（`.dcard`）是全站唯一允许的深色区域**，用于承载"这一个数值最重要"的信息。

| 元素 | 规格 |
|---|---|
| 容器 | 圆角 16px / 32rpx；内边距 16px / 32rpx；背景 `linear-gradient(148deg,#0F3563,#0B2A50)`；阴影 `0 12px 28px rgba(16,58,107,.18)` |
| 标签 | 12.5px / 600，颜色 `--on-data-dim` |
| 主数值 | 34px / 800，等宽数字，颜色 `#EAF3FF` |
| 单位 | 14px / 700，颜色 `--data-accent`（竞技青） |
| 变化提示 | 胶囊 12.5px / 700，正向用 `rgba(63,196,138,.16)` + `#8FE3B8`，目标/当前用 `rgba(255,196,107,.18)` + `#FFC46B` |
| 进度条 | 高 7px 胶囊；轨道 `rgba(255,255,255,.24)`；填充 `--data-accent` |
| 装饰 | 仅允许 2 个细线圆环（1px，透明度 ≤0.22），位于右下角；**所有文本必须 `position:relative; z-index:1`** |
| 数据条 | 4 列 `.dstrip`（应到/已签/迟到/待签），数值 20px/800，语义色区分 |

**防溢出让位规则**：数据卡内数值列最多 4 列；每列最小宽 68px，超出时改为 2×2 网格；数值与单位不得换行导致高度跳动。

**禁止**：数据卡内放长段说明文字；一个页面出现 2 张以上深蓝数据卡（学生首页 1 张、工作台 1 张、统计页 1 张为上限）。

## 9. 表单规范

1. **分组优先**：每个表单页按业务语义分为 2—4 组（如考勤：训练安排 / 签到地点 / 签到规则），每组字段 ≤ 5 个；使用可折叠分组，默认展开当前必须填写的组。
2. **标签在框外**：标签位于输入框上方（左标签右值仅用于"字段组"式的紧凑只读行）；**禁止用占位符代替标签**。
3. **必填标记**：`*` 使用 `--danger`，并在分组标题右侧显示"必填 N 项"。
4. **单位常驻**：数值字段的单位固定在数值旁（`150 米`、`180 秒`），不写在标签里。
5. **字段说明**：每个存在歧义的字段下方给 12.5px 说明（如"精度差于该值时进入待核实"）；说明文字使用 `--ink-3`。
6. **渐进展开**：非核心参数默认折叠为一行（"其他参数：目标 · 负荷 · 注意事项"），展开后仍使用统一字段样式。
7. **类型化核心参数**：训练计划按训练类型渲染核心参数；切换类型时**保留已填值的字段**，仅替换不适用字段的展示。
8. **多条目**：可添加多个训练内容，每条显示类型标签与参数摘要；删除后回到空状态。
9. **提交保护**：主操作在必填未完成时 `disabled`；提交中显示 loading 并禁用重复点击；失败时就地显示原因（不使用整屏弹窗）。
10. **触控**：所有输入与步进控件有效触控高度 ≥ 44px；数字步进按钮 44×44px。
11. **日期与时间**：使用原生 picker；时间为 `HH:mm`、日期为 `YYYY-MM-DD`，显示时补充星期。

## 10. 导航规范

| 层级 | 规范 |
|---|---|
| 小程序原生导航栏 | 使用原生 `navigationBar`（标题 + 可选返回）；**不使用自定义导航栏**，避免安全区与胶囊按钮适配成本 |
| 页面标题 | 主标题为业务对象（如"新建考勤场次"），副标题为范围与状态（如"短跑一组 · 未保存"） |
| 底部 TabBar | 角色工作台采用 4 项 TabBar：学生（首页/训练/数据/我的）、教练（工作台/学员/统计/我的）、developer（工作台/账号/全局/维护）。**TabBar 为提案形态，需所有者确认后实施** |
| 子页面 | 使用返回 + 标题，不使用大标题 + 长说明 |
| 页内切换 | 同层级筛选使用 `.tabs` 胶囊或 `.seg` 分段控件；不使用下拉菜单承载 3 项以内的选择 |
| 折叠分组 | 用于表单分组，不用于导航 |
| 面包屑 | 小程序内不使用面包屑；层级通过标题 + 返回表达 |

**导航一致性**：同一角色下，TabBar 顺序、图标语义与选中色全站一致；选中色统一为 `--brand-700`。

## 11. 空状态规范

| 项 | 规范 |
|---|---|
| 结构 | 图标（44px 圆角块，品牌浅底）+ 标题（14px/700）+ 说明（12.5px，≤2 行，≤40 字）+ 1 个次级按钮（可选） |
| 高度 | 内容高度 ≤ 240px / 480rpx；不使用大面积留白 |
| 文案 | 说明"为什么空"而不是"没有数据"；例如"当前没有赛事意向待处理 / 赛事发布后，学生提交的意向会出现在这里" |
| 按钮 | 提供唯一前进动作（"查看已结束的赛事意向"）；无动作时省略按钮，不留禁用按钮 |
| 与加载态区分 | 加载中使用骨架屏；空状态不使用骨架屏 |
| 错误态 | 错误使用 `--danger` 文字 + 重试按钮，样式与空状态区分（不共用图标） |

## 12. 交互反馈

| 交互 | 反馈 | 规格 |
|---|---|---|
| 按钮点击 | 轻微缩放 + 亮度变化 | `transform: scale(.985)`、120ms |
| 提交类操作 | 按钮 loading + 禁用 | 成功后轻提示；不可重复提交 |
| 列表行处理（审核/审批/评价） | 行淡出移除 + 轻提示 + 计数刷新 | 淡出 180—200ms，提示文案含"模拟/已完成"语义 |
| 数值步进 | 数值即时更新，关联可视元素同步 | 如签到半径步进 → 地图半径圈同步（200ms 过渡） |
| 筛选切换 | 数据区即时更新，无需二次确认 | 周期/训练组/指标切换均即时生效 |
| 折叠展开 | 箭头旋转 90° + 内容展开 | 200ms |
| 签到 | 按钮转为"已签到"并禁用，状态标签变绿 | 一次成功，重复点击给出提示 |
| 长按/滑动 | 本版本不引入滑动手势 | 避免与小程序原生手势冲突 |
| 错误 | 就地显示（字段下方）或轻提示 | 不使用整屏弹窗承载字段级错误 |
| 危险操作 | 二次确认弹窗 + 明确后果文案 | 后续实施轮接入 `wx.showModal` |

**信息性反馈原则**：只对"用户刚做的动作"给出反馈；不对"系统状态未变"做重复提示。

## 13. 三角色差异

三者共享同一套令牌与组件，仅在**首屏分区顺序与信息重点**上不同。

| 角色 | 首屏顺序（自上而下） | 首屏必须可见 | 角色标识 |
|---|---|---|---|
| **学生** | 今日训练（含签到入口）→ PB 数据卡 → 目标与出勤 → 近期进步 → 需要注意 → 常用入口 | 今天要做什么 + 一个主动作（签到） | `学生`（品牌浅底标签） |
| **教练** | 今日训练与考勤状态 → 待办队列（可切换分类）→ 常用管理功能 | 今天考勤状态 + 待处理事项 | `教练员` |
| **developer** | 系统运行状态（数据卡）→ 待处理事项 → 账号与权限分组 → 全局业务管理分组 → 安全边界说明 | 系统状态 + 待处理 + 分组入口 | `开发者` |

**强制规则**：
1. developer 进入任何共享页面时，角色文案必须是"开发者 / 全局"，**不得出现"教练端"或 `COACH` 字样**。
2. developer 页面不展示不必要的敏感身份信息（身份证件、手机号、GPS 原始坐标、请假原因）。
3. 三角色不得出现"学生用深色、教练用蓝色、developer 用绿色"之类按角色切换配色体系的做法。
4. 学生端允许使用能量橙作为主动作色；教练与 developer 端仅将能量橙用于最高优先级待办与"当前/最优"标记。

## 14. 微信小程序适配要求

1. **导航**：使用原生 `navigationBar` 与原生 `tabBar`；不引入自定义导航栏，避免与胶囊按钮、状态栏安全区冲突。
2. **安全区**：底部固定操作条与 TabBar 使用 `padding-bottom: env(safe-area-inset-bottom)`；顶部不额外叠加自定义 padding。
3. **滚动**：页面主体使用页面级滚动（不使用 `scroll-view` 包裹整页），仅横向标签行使用 `scroll-view scroll-x`。
4. **单位换算**：本规范所有 px 值按 `rpx = px × 1.923` 取整到 2 的倍数（见第 4、6 节换算列）。
5. **字体**：不嵌入自定义字体文件（包体积）；数字等宽依赖系统可用字体回退链（`DIN Alternate → SF Mono → Consolas → monospace`），小程序端使用 `font-feature-settings:'tnum'` 保证对齐。
6. **图片与图标**：图标使用内联 `svg` 精灵（原型）→ 小程序端改为 `icon`/`image` 或现有图标方案；**不引入图标库依赖**。
7. **地图与定位**：
   - P1（首选）`wx.chooseLocation`：需在微信公众平台「开发 → 开发管理 → 接口设置」开通，且在 `app.json` 的 `requiredPrivateInfos` 中声明 `chooseLocation`；未开通会在代码审核被拦截。
   - P2（保底）`<map>` 组件 + `bindtap` 取点：不需要定位权限，用 `circles` 画半径、`markers` 画中心点。
   - P3（兜底）手动输入坐标，默认隐藏。
   - **不采用**需付费的地图个性化样式与需 key/配额的地图服务 API。
   - 隐私：《用户隐私保护指引》需声明位置信息用途；仅在用户主动操作时取一次位置，不做持续定位。
8. **数据写入**：所有写操作仍由云函数校验身份与范围；前端不得因为 UI 改版新增直连数据库的写入。
9. **弱网与室外可读**：状态色与文字对比度按第 3 节执行；关键状态同时使用**文字 + 颜色**（不单靠颜色区分），保证强光下可辨。
10. **屏幕适配**：以 375×812 与 390×844 为基准验证；布局使用弹性单位，卡片网格使用 `repeat(2, minmax(0,1fr))` 防止内容撑破。

## 18. 真机验收标准

### 18.1 视觉一致性
1. 全站颜色、字号、间距、圆角、阴影全部来自设计令牌，无页面级硬编码色值。
2. 同一语义（成功/警告/危险/当前）全站同色同形。
3. 三个角色页面共享同一视觉体系，仅信息布局不同。

### 18.2 可读性与触控
4. 正文 ≥14px（27rpx）；说明文字 ≥12.5px（24rpx）；不使用 <11.5px 的字号承载句子。
5. 所有可点击元素有效触控范围 ≥44×44px。
6. 关键文本对比度 ≥4.5:1；重要数值 ≥3:1 且字号 ≥32rpx。
7. 数据卡无文字溢出、无换行跳动；数值列 ≤4 列。

### 18.3 布局与适配
8. 375×812 与 390×844 下均无横向滚动、无文字截断、无元素重叠、无导航遮挡。
9. 底部 TabBar 与固定操作条不遮挡内容，并正确处理安全区。
10. 三种状态（加载/空/错误）在两种尺寸下均正常。

### 18.4 交互
11. 第 16 节列出的 12 项交互全部可用且反馈明确。
12. 纯展示控件必须有明确标注，不得冒充已实现功能。

### 18.5 业务与回归
13. 阶段1—阶段6 共 255 项自动化测试全部通过。
14. 结构校验 1406 项与 `wxml-lint` 通过。
15. PB 计算规则、考勤统计口径、成绩审核、赛事状态机、训练计划字段契约均未改变（有回归测试证明）。
16. 云函数 `api` 未因 UI 改版重新部署（除经批准的只读聚合接口外），数据库仍为 19 个集合。

### 18.6 性能
17. 主包体积较改造前增幅 ≤10%。
18. 工作台首屏在 iPhone 上 1.5s 内可见主要内容（含骨架屏）。
19. 单页新增云函数调用 ≤2 个。
