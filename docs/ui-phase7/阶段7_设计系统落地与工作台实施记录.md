## 1. 设计系统落地（阶段7-1）

### 1.1 落地方式

- 在 `miniprogram/app.wxss` **追加**一段阶段7样式（文件末尾），全部使用 `jg-` 命名空间。

## 2. 三个工作台改造（阶段7-2）

### 2.1 学生工作台（`pages/student/`）

- 结构顺序：**今日训练（含签到入口）→ 个人 PB（深蓝数据卡）→ 出勤与目标指标 → 近期进步 → 俱乐部通知 → 常用功能（6 个瓦片 + 5 行入口）**。
- 今日训练显示真实场次的时间窗口、地点、训练组与状态；状态为"待签到"时按钮为橙色"去签到"，其余为"查看考勤详情"。**签到仍进入现有 `student-attendance` 页面完成 GPS 签到流程，工作台不复制签到逻辑。**
- PB 数据卡显示真实 `personalBests[0]`（赛事项目、数值、单位、取得日期），并展示体考目标与已审核成绩条数；**无已审核成绩时显示说明性空状态，不显示任何演示数字。**
- 出勤率取自 `statistics.get_my_overview`，展示有效出勤 / 实际应签到与迟到、未签到、待核实数量，并保留服务端返回的统计口径说明。
- 近期进步取自阶段变化（最多 3 条），使用"首次 → 最新"文案与提升幅度。
- 通知区展示最多 3 条，重要通知使用红色"重要"标签，未读使用品牌标签；未读数与"查看全部"文案由真实接口返回。

### 2.2 教练工作台（`pages/coach/`）

- 结构顺序：**今日训练与考勤（含名单统计）→ 待办（可分类筛选）→ 赛事报名意向 → 待审核注册 → 常用管理入口**。
- 今日考勤显示真实场次信息，并对**第一场（当前焦点场次）**额外加载名单统计（应到 / 已签到 / 迟到 / 待签到 + 已批准请假 / 待核实异常）。其余场次只展示场次信息与"查看名单"入口，避免为每个场次都发起请求。
- 待办为**统一待办列表**，合并三类真实来源：待批请假（最高优先级）、待审成绩、需关注反馈；支持"全部 / 待批请假 / 待审成绩 / 需关注反馈"客户端筛选（不产生额外请求），并显示每类数量。
- **待办行只做跳转，不做写入**：点击"去审批 / 去审核 / 去评价"分别进入 `attendance-manage`、`coach-performance-review`、`feedback-manage`，由业务页面展示必要信息并二次确认后写入。已由单元测试断言：点击待办不会调用任何写入接口。
- 保留原有"待审核注册"能力（这是教练端唯一的注册审核入口），通过 / 驳回均使用 `wx.showModal` 二次确认，驳回可填写意见。

### 2.3 开发者工作台（`pages/admin/`）

- 结构顺序：**系统运行状态（深蓝数据卡）→ 待处理事项（含待审核注册）→ 账号与角色 → 训练组与教练范围 → 全局管理入口 → 审计与安全边界**。
- 系统状态全部使用真实数据：`health_check` 返回的云函数与数据库状态、`config/env.js` 的云环境 ID、`admin.list_users` 的账号总数、`admin.list_training_groups` 的训练组数、待处理合计。
- **去掉了 8 个纵向大按钮**：改为按职责排序的管理入口列表（成绩审核 / 考勤管理 / 统计工作台 / 训练计划 / 赛事管理 / 通知管理 / 训练反馈管理），每行都是已注册的真实页面。
- **账号与角色、训练组与教练范围默认收起**，只显示统计摘要；展开后才是完整的角色授予/撤销、账号启用/停用、查看档案、训练组启停、创建训练组、教练范围分配。这样既解决"大量纵向大按钮"，又不丢失任何原有管理能力。
- 角色文案统一为「开发者」，页面内不出现 `COACH` 模块名或"教练端"字样（已由结构校验与单元测试断言）。
- 不展示不必要的敏感身份信息（不展示 OpenID、身份证件、手机号、GPS 原始坐标）。
- 审计入口以说明形式给出：关键操作写入云端审计日志，查看需在云开发控制台进行，**不提供点击无响应的假入口**。
- DEMO 预览入口保留，但受 `isDemoAllowed()` 环境开关控制（仅开发/预览环境显示），演示数据不进入任何正式统计。

### 4.4 加载方式与失败表现

- **逐区块独立加载**：每个区块独立维护 `loading / error / data`，使用 `settle()` 包装每个请求，**单个接口失败只影响对应区块**，其余区块正常渲染。
- **逐区块重试**：每个失败区块都提供"重新加载"按钮，只重试该接口。
- **部分失败容忍**：教练待办的三个来源中只要有一个成功就展示已取得的待办（仅当三者全部失败才整体报错）；开发者待处理统计同样容忍单侧失败。
- **下拉刷新**：三个工作台均启用 `enablePullDownRefresh`，`onPullDownRefresh` 重新加载全部区块并在完成后调用 `wx.stopPullDownRefresh()`。
- **兼容兜底**：接口在运行环境不可用时会被 `safeCall()` 捕获为区块错误，不会导致整页白屏。

## 7. 已知问题与技术风险

1. **教练工作台请求数偏多（7 个）**：由于本轮未批准新增"工作台只读聚合接口"，教练端需要 6 个并行请求 + 1 个顺序请求。在弱网或云函数冷启动叠加时，首屏完成时间可能偏长（区块会逐个渲染，不会白屏）。建议后续评估一个只读聚合接口（需另行批准）。
2. **每日考勤统计只对焦点场次加载名单**：当同一天存在多个场次时，只有第一场显示应到/已签数字，其余需进入考勤管理查看。这是为避免 N+1 请求做的取舍。
3. **CSS 变量兼容性**：令牌使用 `var(--x, 字面值)` 形式，即使基础库不支持变量也能正常显示；但若后续修改令牌值，需注意字面值兜底也需要同步更新。
4. **未验证真机渲染**：本机无微信开发者工具 CLI，`wxss` 的渐变、阴影与安全区在低端 Android 上的表现需真机确认。
5. **DEMO 入口**：仅在开发/预览环境显示，正式环境自动隐藏；该入口沿用阶段2的既有实现，未做改动。
6. **未引入 TabBar**：三个工作台目前没有底部导航，页面内入口以列表形式呈现。若后续确认引入 TabBar，需要单独提交路由迁移方案。
