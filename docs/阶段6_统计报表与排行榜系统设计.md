# 阶段6｜统计报表与排行榜系统设计

**日期：2026-10-13**
**状态：本地开发、自动化测试、必要索引、阶段6 API部署和非破坏性基础验证已完成；真实统计业务验收待阶段T。**

## 1. 目标与范围

阶段6将阶段1至阶段5的真实业务数据转化为可用于训练、管理和运营的统计结果：

- 6-A：学生个人训练数据统计。
- 6-B：正式运动成绩排行榜。
- 6-C：训练考勤统计与排行榜。
- 6-D：教练统计工作台。
- 6-E：正式成绩与考勤XLSX导出。

本阶段复用现有 `api`、身份认证、角色权限、repository、日期工具、审计和XLSX能力，不新增统计集合或缓存集合。

第三方体测仪器、设备SDK、设备连接和自动导入继续保持永久取消。

## 2. 数据来源与真实性

统计只读取现有业务数据：

| 集合 | 用途 |
|---|---|
| `student_profiles` | 学生姓名、专项、体考目标 |
| `training_groups` | 训练组、负责教练、启用状态 |
| `group_memberships` | 学生训练组归属和成员关系时间范围 |
| `performance_records` | approved 正式成绩、历史PB和周期最好成绩 |
| `attendance_sessions` | 有效训练场次、取消场次和时间范围 |
| `attendance_records` | 签到、迟到、待核实、未签到和人工核实结果 |
| `leave_requests` | 已批准请假，不输出请假原因 |
| `training_feedback` | 反馈次数、完成情况、RPE和教练评价情况 |

禁止使用DEMO数据、pending成绩、rejected成绩、无效记录或前端伪造数据进入正式统计。无真实数据时返回空统计或0，不生成虚假运营指标。

## 3. 统计周期

所有统计周期由服务端按UTC+8计算：

- `month`：自然月，范围为 `[YYYY-MM-01, 下月第一天)`。
- `quarter`：Q1=1—3月，Q2=4—6月，Q3=7—9月，Q4=10—12月，范围为 `[季度首日, 下季度首日)`。
- `year`：自然年，范围为 `[YYYY-01-01, 下一年01-01)`。

成绩周期归属使用 `achievedAt` 成绩实际发生日期，不使用审核完成日期。考勤周期归属使用 `attendanceDate` 场次业务日期。

## 4. 成绩统计口径

### 4.1 正式PB

- 只使用 `status=approved`。
- 按学生和项目分别计算。
- 计时项目取最小值，距离和高度项目取最大值。
- 同一值并列时使用稳定的成绩日期和记录ID作为显示排序键，但历史PB值不变。

### 4.2 周期最好成绩

- 先按服务端统计周期过滤 `achievedAt`。
- 同一学生同一项目同一周期只保留一条最好成绩。
- 周期排行榜只使用该周期内的最好成绩，不把历史PB放入周期榜。
- 历史PB作为单独字段或独立页面展示，不参与周期排名。

### 4.3 排名

- 计时项目升序排列。
- 距离和高度项目降序排列。
- 不混合不同项目和不同单位。
- 同成绩使用标准竞赛并列排名：`1、2、2、4`。
- 并列成绩显示顺序使用稳定键，但不破坏并列名次。

## 5. 考勤统计口径

### 5.1 场次状态

- `cancelled`：不计入应到、出勤率或排行榜分母。
- `not_started`：显示为未开始，不提前计为未签到。
- `open`：显示为签到中，不计入最终出勤率分母。
- `closed`：可以计入已完成统计。

### 5.2 学生状态

- `checked_in`：正常签到，计入有效出勤。
- `late`：迟到，计入有效出勤，同时计入迟到次数。
- `leave_approved`：已批准请假，从实际应签到分母排除，不计入无故缺勤。
- `pending_verification`：待核实异常，单独列示，不直接视为正常出勤。
- `absent`：签到窗口结束后未签到，显示为“未签到”，不能自动描述为已核实无故缺勤。

### 5.3 统计公式

```text
实际应签到人数 = 计划应到人数 - 已批准请假人数
有效出勤人数 = checked_in + late + 人工核实为到场
出勤率 = 已结束场次有效出勤人数 / 已结束场次实际应签到人数
迟到率 = 迟到人数 / 有效出勤人数
```

分母为0时返回 `null`，显示“暂无有效统计”，不显示虚假的100%。

考勤排行榜会显示样本场次数。默认最低样本门槛为3场；样本不足时显示数据但不分配排名，避免一次签到形成错误领先评价。

## 6. 历史成员范围限制

当前 `group_memberships` 使用一个学生在训练组中的当前/最后关系文档，没有每场考勤的名单快照。统计仅能依据：

- 成员关系中的 `assignedAt`、`removedAt`。
- 历史 `attendance_records` 和已批准请假记录。
- 训练场次创建时可见的历史签到记录。

因此服务端对历史统计返回：

- `membershipHistoryReliable=false`。
- `membershipHistoryEstimated=true`。
- 明确的 `membershipHistoryNote`。

历史出勤率不得被描述为逐场精确名单结果。后续如需要在阶段T后提升精度，可设计“场次名单快照”或“带有效期的成员关系版本”，但本轮不修改数据库。

## 7. API 设计

统一使用现有 `api` 云函数入口：

| 接口 | 角色 | 说明 |
|---|---|---|
| `statistics.get_meta` | student/coach/developer | 返回可访问训练组、项目和最低样本门槛 |
| `statistics.get_my_overview` | student | 本人成绩、考勤、反馈和目标统计 |
| `statistics.get_manage_overview` | coach/developer | 授权范围的管理总览和训练组比较 |
| `leaderboard.performance` | 三种角色 | 按项目、周期、训练组查询正式成绩榜 |
| `leaderboard.attendance` | 三种角色 | 按周期、训练组查询考勤率和出勤统计 |
| `export.performance_rows` | 三种角色 | 导出approved成绩XLSX行数据 |
| `export.attendance_rows` | 三种角色 | 导出考勤XLSX行数据 |

学生调用排行榜时，服务端只允许本人所在训练组范围，并对非本人姓名做脱敏；教练只能访问负责训练组；developer按现有全局权限访问。

## 8. 权限与隐私

- 所有角色、训练组、学生范围和可见性均由服务端根据可信微信身份重新计算。
- 客户端提交的 role、OpenID、studentUserId、coachUserId 和排名结果不作为授权依据。
- 学生排行榜默认脱敏展示其他学生姓名。
- 不返回身份证号、联系电话、出生日期、身体指标详情、请假原因、GPS坐标或私人训练反馈。
- 教练只能管理授权训练组；developer沿用现有全局权限，不新增第二套超级管理员机制。
- 停用账号和停用训练组继续遵守阶段1权限规则。

## 9. 查询与分页

- 成绩和考勤历史使用确定性排序；成绩按 `achievedAt asc, _id asc`，考勤按业务日期和记录ID稳定排序。
- 统计读取超过上限时返回 `STATISTICS_INCOMPLETE`，不返回看似完整的错误结果。
- 导出默认最多2000行；超过上限返回 `EXPORT_RANGE_TOO_LARGE`，提示缩小周期或训练组，不静默截断。
- 统计结果不建立新的缓存集合。当前规模为100—300名学生，优先使用现有集合和组合索引，真实规模性能由阶段T抽样验证。
