## 1. 目标与结论

在 student / coach / parent / developer 四个工作台上补齐可实际使用的「全部功能」入口，并提供一个统一的功能分类页面。要求只对接已经真实实现的业务页面，不新增假入口，不扩大任何角色权限。

结论：**已完成**。四个角色均有入口，统一进入 `pages/all-features/all-features`，目录只收录已在 `app.json` 注册且文件真实存在的页面。

## 2. 架构：统一配置 + 角色差异化展示 + 单个可复用页面

| 文件 | 职责 |
|---|---|
| `miniprogram/config/feature-catalog.js` | 唯一功能目录配置；`categoriesForRole` / `featuresForRole` / `availableRoles` / `allRoutes` / `hasCatalog` |
| `miniprogram/utils/active-role.js` | 多角色账号的“当前激活角色”记忆（与 userId + 角色集合绑定） |
| `miniprogram/pages/all-features/all-features.{js,json,wxml,wxss}` | 四角色共用的功能分类页 |
| `pages/role-select/role-select.js` | 多角色选择时记录激活角色 |

安全边界：**目录只用于前端展示与导航，不构成权限依据**。所有数据访问仍由云函数按可信微信身份重新校验角色与数据范围；隐藏入口不能替代服务端鉴权。

## 3. 四角色实际分类

**学生**：训练与计划（训练计划 / 签到与请假 / 训练反馈）、成绩与数据（成绩申报 / 运动数据报告 / 训练统计 / 成绩排行榜 / 考勤统计与排行）、赛事与通知（赛事意向 / 俱乐部通知）、个人中心（完善个人档案 / 亲子关联）。

**教练**：训练管理（训练计划 / 考勤管理）、学生与成绩（成绩审核 / 统计与排行）、赛事与沟通（赛事管理 / 通知管理 / 训练反馈管理）。

**家长**（只读）：我的学生（家长工作台 / 关联学生管理）。无任何写入类入口，入口仅指向 `/pages/parent/parent` 与 `/pages/parent-bind/parent-bind`。

**开发者**：审核与核验（注册审核与账号管理 / 家长关联审核）、全局业务管理（成绩审核 / 考勤管理 / 统计工作台 / 训练计划 / 赛事管理 / 通知管理 / 训练反馈管理）、系统视角（查看教练工作台）。

## 5. 多角色与账号状态处理

1. 目录按固定顺序（student → coach → parent → developer）取当前会话中已授权且存在目录的角色。
2. 激活角色记忆与 `userId + roles` 绑定：账号切换、角色增减、账号停用后自动失效并回退到第一个可用角色。
3. 退出登录调用 `clearActiveRole()`，避免下一位使用者读到旧角色。
4. 非 `active` 账号或没有可展示目录时，不渲染任何功能入口，`reLaunch` 回会话入口。

## 8. 限流并发阈值复核（任务 G）

`redeemInvite` 的失败限流由两部分组成：

1. **账号级窗口限流**：`recordParentInviteFailure` 使用原子 `db.command.inc(1)`，并发失败请求不会互相覆盖计数（已修复过“读-改-写丢更新”）。
2. **凭证级上限**：`incrementInviteAttempts` 同样使用原子自增。

**结论（PASS，非缺陷）**：计数更新本身是原子的，不存在计数丢失或计数被覆盖；阈值判断位于自增之前，属于“检查-再自增”的软限制。在刚好低于阈值时并发爆发，可能让窗口内有效拒绝的失败数略高于 10（例如 10~15），但攻击者累计尝试仍被限制在单位数级，无法无界枚举 6 位凭证，也无法绕过凭证本身的 `maxAttempts` 与哈希比对。按“未发现确定缺陷则不做不必要重构”的原则，保留现实现并在验收报告标注为已知特性。
