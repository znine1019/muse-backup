# 阶段1｜云端部署与测试清单

**适用范围：**  `cloud1` 开发测试环境  
**环境 ID：** `cloud1-d8g0egkli3191959a`  
**前置约束：** 本清单中的所有操作都需要用户确认后手动执行。不得在未确认前部署到正式环境或写入真实学生信息。

## 1. 创建数据库集合

在微信开发者工具的“云开发 → 数据库”中，为 `cloud1` 创建以下集合：

| 集合名 | 用途 |
|---|---|
| `users` | 用户身份映射、账号状态、服务端角色 |
| `student_profiles` | 学生注册档案和审核状态 |
| `role_bindings` | 当前角色绑定状态；授权/撤销历史在 `audit_logs` |
| `registration_reviews` | 注册提交与审核记录 |
| `training_groups` | 训练组基础信息、年度/周期和稳定 groupId |
| `group_memberships` | 教练员、学生与训练组关系 |
| `audit_logs` | 身份、权限和审核审计记录 |
| `system_config` | 首位开发者初始化状态 |

所有集合先设置为：

```text
仅管理员可读写
```

云函数使用服务端 SDK 访问数据库，不受客户端权限规则限制。前端不允许直接读写这些集合。

在 `system_config` 中手动创建文档：

```text
文档 ID：bootstrap
字段：developerInitialized = false
字段：state = ready
```

该文档是初始化事务的并发控制点。初始化成功后 `developerInitialized` 会永久变为 `true`，不得手工改回 `false`。

### 1.1 字段最终结构

#### users

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 服务端确定性用户 ID，前缀 `usr_` |
| `_openid` | string | 微信云函数可信 OpenID，唯一 |
| `unionid` | string | 可选，服务端上下文返回时保存 |
| `status` | string | `pending_profile`、`pending_review`、`active`、`rejected`、`disabled` |
| `roles` | string[] | 当前角色：`developer`、`coach`、`student` |
| `schemaVersion` | number | 阶段1为 `1` |
| `createdAt` / `updatedAt` | date | 服务端时间 |

#### student_profiles

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 确定性档案 ID |
| `userId` | string | 指向 `users._id`，唯一 |
| `name` / `gender` / `birthDate` | string | 注册基础资料 |
| `heightCm` / `weightKg` | number | 技术校验范围内的数值 |
| `primaryTrainingProject` | string | 主要训练项目 |
| `requestedTrainingGroupId` | string | 申请的训练组稳定 ID |
| `reviewStatus` | string | `pending`、`approved`、`rejected` |
| `currentReviewId` | string | 当前审核记录 ID |
| `reviewComment` / `reviewedBy` | string | 审核意见和审核人 |
| `submittedAt` / `reviewedAt` / `updatedAt` | date | 服务端时间 |
| `schemaVersion` | number | 阶段1为 `1` |

#### role_bindings

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 确定性角色绑定 ID |
| `userId` | string | 用户 ID |
| `role` | string | `developer`、`coach`、`student` |
| `status` | string | 当前为 `active` 或 `revoked` |
| `grantedBy` / `grantedAt` | string / date | 当前有效授权信息 |
| `revokedAt` | date | 当前记录被撤销时保存 |
| `updatedAt` | date | 服务端时间 |

授权与撤销历史由 `audit_logs` 保存。重复授权使用固定文档写入，因此撤销后可以重新授权。

#### registration_reviews

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 每次提交的确定性审核记录 ID |
| `userId` / `profileId` | string | 用户和档案关联 |
| `status` | string | `pending`、`approved`、`rejected` |
| `comment` | string | 审核意见 |
| `submittedAt` / `createdAt` / `reviewedAt` | date | 服务端时间 |
| `reviewedBy` | string | 审核人用户 ID |

#### training_groups

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 数据库文档 ID，同时作为业务引用 ID |
| `groupId` | string | 独立稳定训练组 ID，与 `_id` 一致 |
| `name` | string | 训练组展示名称，允许跨周期同名 |
| `seasonLabel` | string | 年份或周期，如 `2026春季` |
| `enabled` | boolean | 是否启用 |
| `createdBy` | string | 创建开发者用户 ID |
| `createdAt` / `updatedAt` | date | 服务端时间 |
| `schemaVersion` | number | 阶段1为 `1` |

训练组业务身份只使用 `groupId`，不以训练组名称判断身份。`groupId` 由规范化名称和 `seasonLabel` 确定性生成。

#### group_memberships

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 确定性成员关系 ID |
| `userId` / `groupId` | string | 用户和训练组稳定 ID |
| `roleInGroup` | string | `coach` 或 `student` |
| `status` | string | `active` 或 `inactive` |
| `assignedBy` | string | 授权开发者用户 ID |
| `assignedAt` / `removedAt` / `updatedAt` | date | 服务端时间 |

#### audit_logs

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 系统生成或确定性审计 ID |
| `actorUserId` | string | 操作人用户 ID |
| `action` | string | 审计动作名称 |
| `targetType` / `targetId` | string | 操作对象 |
| `result` | string | 操作结果 |
| `metadata` | object | 仅非敏感必要信息 |
| `createdAt` | date | 服务端时间 |

#### system_config

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | `bootstrap` 固定文档 |
| `developerInitialized` | boolean | 初始为 `false`，成功后永久为 `true` |
| `state` | string | 初始为 `ready`，成功后为 `completed` |
| `initializedBy` | string | 首位开发者用户 ID |
| `initializedAt` / `updatedAt` | date | 服务端时间 |

## 2. 建议索引

在数据库控制台中手动创建：

| 集合 | 索引字段 | 唯一 |
|---|---|---|
| `users` | `_openid` 升序 | 是 |
| `users` | `roles` 升序 | 否 |
| `student_profiles` | `userId` 升序 | 是 |
| `student_profiles` | `reviewStatus` 升序、`requestedTrainingGroupId` 升序 | 否 |
| `role_bindings` | `userId` 升序、`role` 升序 | 是 |
| `registration_reviews` | `userId` 升序、`status` 升序 | 否 |
| `registration_reviews` | `createdAt` 降序 | 否 |
| `training_groups` | `groupId` 升序 | 是 |
| `training_groups` | `name` 升序、`seasonLabel` 升序 | 否 |
| `group_memberships` | `groupId` 升序、`userId` 升序 | 是 |
| `group_memberships` | `userId` 升序、`roleInGroup` 升序、`status` 升序 | 否 |
| `group_memberships` | `groupId` 升序、`roleInGroup` 升序、`status` 升序 | 否 |
| `audit_logs` | `actorUserId` 升序 | 否 |
| `audit_logs` | `createdAt` 降序 | 否 |

如果控制台提示复合索引名称或排序方式不兼容，以控制台实际要求为准，不要删除业务字段。

补充说明：

- `_id` 默认唯一，无需重复创建普通 `_id` 索引。
- `users._openid` 唯一索引与登录代码兼容：服务端先用确定性用户 ID 查询，再用 `_openid` 回查，创建冲突时再次回查，避免同一 OpenID 创建重复账号。
- `role_bindings.userId + role` 唯一索引只描述当前绑定；每次授权和撤销状态变化写入 `audit_logs`，撤销后同一固定文档可重新激活。
- `training_groups.groupId` 是业务身份，`name + seasonLabel` 仅用于展示和人工判断，不设全局名称唯一索引。
- `system_config` 只使用固定 `_id = bootstrap`，不需要额外普通索引。

## 3. 部署云函数

在微信开发者工具中：

1. 展开 `cloudfunctions/health_check`。
2. 右键选择“上传并部署：云端安装依赖”。
3. 等待部署成功。
4. 展开 `cloudfunctions/api`。
5. 右键选择“上传并部署：云端安装依赖”。
6. 等待 `wx-server-sdk` 安装并部署成功。

不要只上传代码而跳过云端依赖安装。两个云函数都使用：

```javascript
cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV });
```

因此它们会运行在部署时选择的 `cloud1` 环境中，不需要也不允许把前端环境 ID 再写入云函数。

## 4. 配置开发者初始化凭据

先让预定的首位开发者通过小程序完成一次普通登录，在 `users` 集合中核对其 `_openid`。不要把该 OpenID 发到聊天或公开文档。

```text
变量名：BOOTSTRAP_ADMIN_OPENIDS
变量值：允许执行首次初始化的服务端可信 OpenID；多个 OpenID 用英文逗号分隔
```

然后再增加一次性码：

在 `api` 云函数的配置中找到“环境变量”，增加：

```text
变量名：BOOTSTRAP_ADMIN_CODE
变量值：由用户自行生成并妥善保存的强随机字符串，至少 16 位
```

安全要求：

- 不要把初始化码写入代码、聊天、Git、README 或截图。
- 不要在前端保存 `BOOTSTRAP_ADMIN_OPENIDS` 或任何初始化凭据。
- 初始化码只用于首位开发者账号建立。
- 系统已有有效开发者后，初始化接口会拒绝再次初始化。
- 首位开发者初始化成功后，应立即删除 `BOOTSTRAP_ADMIN_CODE` 和 `BOOTSTRAP_ADMIN_OPENIDS`，并重新部署或重启 `api` 云函数。
- 初始化必须同时满足可信 OpenID 白名单、正确初始化码和未完成的初始化状态。
- 普通登录不会调用初始化接口，也不会自动获得开发者角色。

## 5. 首次连接测试

1. 在微信开发者工具中重新编译小程序。
2. 首页应完成云函数登录调用，并创建 `pending_profile` 用户。
3. 点击“检查连接”。
4. 如果显示“云函数与数据库连接正常”，说明 `health_check` 和 `system_config` 集合均可访问。
5. 如果显示数据库未初始化，检查第 1 节集合是否全部创建。

## 6. 首位开发者初始化

此步骤只能由项目负责人操作：

1. 在微信开发者工具的编译模式中增加页面路径 `pages/bootstrap/bootstrap`。
2. 用项目所有者微信账号打开该页面。
3. 输入第 4 节配置的初始化码。
4. 云函数应在数据库事务中同时写入开发者角色、角色绑定、初始化状态和审计记录。
5. 提交成功后应进入开发者工作台。
6. 检查数据库：
   - `users` 中该账号状态为 `active`，角色包含 `developer`。
   - `system_config/bootstrap.developerInitialized` 为 `true`。
   - `audit_logs` 中存在 `auth.bootstrap.developer_created`。
7. 删除 `api` 的 `BOOTSTRAP_ADMIN_CODE` 和 `BOOTSTRAP_ADMIN_OPENIDS` 环境变量并重新部署。

## 7. 模拟数据测试顺序

所有测试数据必须使用明显虚构的信息。

### 7.1 建立训练组

1. 开发者工作台创建“模拟短跑组”。
2. 年份或周期填写“2026测试周期”。
3. 记录训练组业务 ID `groupId`。

### 7.2 准备教练员

1. 使用第二个模拟微信账号登录，系统创建 `pending_profile` 账号。
2. 开发者工作台为该账号授予 `coach` 角色。
3. 该账号重新打开小程序，确认角色选择中只出现“教练员”。
4. 在开发者工作台把该教练员分配到“模拟短跑组”。

### 7.3 学生注册

1. 使用第三个模拟微信账号登录。
2. 填写虚构学生资料并申请“模拟短跑组”。
3. 提交后确认状态为 `pending_review`。
4. 教练员账号只能在该训练组的待审核列表看到这名学生。
5. 教练员点击“通过”。
6. 学生重新打开小程序，确认状态变为 `active`，可进入学生工作台。

## 8. 权限和越权测试

### 8.1 普通学生调用开发者接口

在学生账号的小程序调试控制台执行：

```javascript
wx.cloud.callFunction({
  name: 'api',
  data: {
    action: 'admin.list_users',
    payload: {}
  }
}).then(console.log)
```

预期结果：`ok: false`，错误码为 `FORBIDDEN`。

### 8.2 学生尝试指定其他学生

在学生账号中调用：

```javascript
wx.cloud.callFunction({
  name: 'api',
  data: {
    action: 'profile.get',
    payload: {
      targetUserId: '其他学生ID'
    }
  }
}).then(console.log)
```

预期结果：云函数忽略 `targetUserId`，只返回调用者本人档案；不能读取其他学生数据。

### 8.3 教练跨组审核

1. 创建第二个训练组。
2. 第二个训练组的年份或周期填写“2027测试周期”。
3. 让一名新模拟学生申请第二个训练组。
4. 使用只负责第一个训练组的教练账号打开工作台。
5. 预期：看不到第二名学生；即使伪造 `targetUserId` 调用审核接口，也应返回 `OUT_OF_SCOPE`。

### 8.4 账号停用与启用

1. 开发者停用一个模拟学生账号。
2. 该学生重新打开小程序，应看到账号已停用且无法进入学生工作台。
3. 学生即使尝试直接调用受保护接口，也应返回 `ACCOUNT_DISABLED`。
4. 开发者重新启用账号后，学生按原有角色恢复访问。

### 8.5 直接访问数据库

在小程序控制台执行：

```javascript
wx.cloud.database().collection('users').get()
```

预期结果：权限规则拒绝客户端直接读取。权限必须继续由云函数验证。

## 9. 尚未验证事项

创建集合和部署云函数后，仍需要重点确认：

- `wx-server-sdk` 与当前微信开发者工具基础库的兼容性。
- 复合索引是否满足实际查询。
- 300 名用户下分页读取的性能。
- 账号停用、角色撤销和多角色切换的真实行为。
- 数据库备份、恢复和审计日志留存策略。
