# V1.6 四角色综合首页规划

**日期**：2026-10-14　**状态**：部分已完成 ｜ 其余待下一批

## 1. 目标

首页像成熟的功能性 App：集中展示并进入大部分常用功能，**优先复用现有工作台，不另建四套重复首页**。四个角色只展示自己真正拥有权限的功能，不出现无法进入的假按钮，也不用隐藏入口代替服务端权限。

## 2. 统一结构

角色信息 → 今日重点 → 核心数据 → 常用功能 → **全部功能（按业务类别组织）** → 重要通知 → 个人中心。

| 角色 | 突出内容 | 现状 |
|---|---|---|
| 学生 | 训练与个人数据 | 已有（今日训练/PB/出勤/进步/通知/常用功能/更多功能） |
| **家长（新增）** | 关联学生的训练情况 | 已实现学生概览/计划/成绩/考勤/反馈/赛事/通知/个人中心 |
| 教练 | 待办与训练管理 | 已有（今日考勤/待办/赛事/常用管理入口） |
| developer | 全局管理与系统状态 | 已有（系统状态/待处理/账号与角色/训练组/全局入口） |

## 3. 全部功能入口

按业务类别组织（下一批收敛为统一分组）：训练（计划/考勤/反馈）、数据（成绩/PB/统计/排行）、沟通（通知/赛事）、账号（档案/关联/身份切换/退出）。

**本轮未做**：三个既有工作台的“全部功能”分组化改造（现有入口已可用但未按类别分组）。

**阶段8第四轮已完成**：四个角色均提供「全部功能」入口，统一跳转到共用的分类页 `pages/all-features/all-features`。
目录由 `miniprogram/config/feature-catalog.js` 单点维护（配置 + 角色差异化展示 + 一个可复用页面），只收录仓库中真实存在且已在 `app.json` 注册的页面。
多角色账号按当前激活角色展示，激活角色记忆在 `miniprogram/utils/active-role.js`（与 userId + 角色集合绑定，账号切换/角色变更/退出登录后自动失效）。

## 4. TabBar

本轮**未批准也未执行**任何原生 TabBar 路由迁移；如需调整，将先提交独立迁移方案。
