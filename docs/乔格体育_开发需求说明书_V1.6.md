# 乔格体育俱乐部数字化训练管理系统

**微信小程序正式开发需求说明书｜V1.6（首版开发基线）**  
**日期：2026年10月12日**  
**状态：一级功能范围已确认；页面细节、业务规则与部分接口权限待开发阶段验证**  
**适用范围：乔格体育俱乐部内部｜个人主体微信小程序**

## 1. 项目概述与目标

建设一套仅面向乔格体育俱乐部内部人员使用的微信小程序，集中管理学生档案、人工训练计划、考勤、请假审批、测试成绩、训练反馈、排行榜和竞赛报名，减少教练员重复录入与线下表格整理。

- **部署形态**：单个微信小程序，按照学生、教练员、开发者／管理员三类身份展示不同工作台，共用一套后端和数据库。
- **预计规模**：学生100—300人，教练员5—10人，管理员1人或少量授权人员；按300名学生容量设计，留有扩展空间。
- **主体与范围**：以用户个人主体注册；小程序供俱乐部内部使用，不开放公众自行加入。
- **开发环境**：Windows电脑、微信开发者工具、Git、VS Code／Codex；DeepSeek API只在开发工具中辅助编码，不接入小程序运行时。
- **后端候选**：优先验证微信开发者工具内的「微信云开发」能力（`wx.cloud`、云函数、数据库、云存储），最终以账号可用能力和预算为准。
- **非目标**：不开发AI训练计划或诊断、不接入AI API到正式小程序、不开发在线支付／会员订阅、多机构入驻及独立PC网站。

## 2. 角色与授权原则

| 角色 | 主要工作 | 数据访问边界 |
|---|---|---|
| 学生 | 首次注册完善档案；查看个人计划、成绩、排行榜；签到、请假、反馈 | 本人档案及被允许展示的内部榜单内容 |
| 教练员 | 管理所属学生与训练组；人工制定计划；管理考勤；审批请假和成绩；导出表格 | 仅负责的学生、训练组和相关业务记录 |
| 开发者／管理员 | 开通、停用账号；分配角色和教练员；配置系统；查看汇总与审计记录 | 根据必要性获得管理权限，重要操作留痕 |

**强制要求**：微信一键身份登录 ≠ 自动获得俱乐部使用权限。首次进入建立待审核档案，教练员身份只能由管理员授权；任何角色和数据归属校验都应在云函数／服务端进行，不能只依靠前端隐藏按钮。允许同一个微信账号拥有多种经授权的角色。

## 4. 核心模块业务要求

### M01｜微信登录与首次注册

1. 用户通过微信身份进行快捷登录，不强制设置账号密码或获取微信手机号。
2. 首次登录创建待激活账号，学生填写档案后提交内部审核；授权通过后进入学生端。
3. 教练员角色由管理员分配，登录后进入教练员工作台；管理员可在已授权的角色间切换。
4. 未授权、停用账号不能访问内部管理数据；退出、会话失效、重复提交应有明确处理。

### M02｜学生注册档案及个人主页

- **基础资料**：姓名、性别、出生日期／年龄、身高、体重等。
- **体育考试信息**：考试省份、考试年份、预计考试日期（如适用）。
- **专项及目标**：主要训练项目、兼项、当前个人最好成绩申报、目标成绩、训练年限／经历。
- **组织关系**：所属训练组、负责教练员；注册阶段可申请绑定，由后台确认。
- **个人主页**：头像、昵称、个人签名、主项、已审核个人最好成绩、累计出勤等。
- **入部天数**：显示“已加入乔格体育 XX 天”，按管理员／教练确认的**实际入部日期**计算，不等同于小程序注册日期。

身高、体重等允许按权限更新并保留必要历史；涉及个人健康／伤病资料仅在明确必要时采集。学生提交的“个人最好成绩”进入待审状态，不可直接成为榜单的有效成绩。

### M03｜训练计划管理（完全人工）

教练员创建单日、每周和多周训练计划，填写训练项目、组数、次数、强度、恢复间隔及备注；支持复制模板、选择训练组／个人下发和后续修改。学生端查看本人计划及更新记录。训练计划由教练员自主制定，**系统不自动生成训练建议**。

### M04｜GPS训练考勤与Excel导出

学生在训练场景中主动同意位置授权并签到／签退。系统记录服务器时间、训练场次、考勤状态及必要的定位判断结果；教练员可查询异常情况并按权限处理。支持按日、周、月、自定义时间、训练组或教练员筛选，生成真实的`.xlsx`考勤表。

**技术前置条件**：个人主体小程序能否获得所需定位接口权限，必须在开发者后台与真机上验证；若不可用，保留动态二维码／教练人工核验等备选路径，不能把GPS视为已经获批。默认不做持续定位，不把学生位置轨迹作为排行榜展示内容。

### M05｜请假审批（独立模块）

学生提交请假类型、起止时间、事由及必要附件；教练员审批、驳回或提出处理意见；记录申请及处理时间。批准的请假与对应考勤关联，避免误算无故缺勤。多级审批、补假及材料规则留到具体模块设计确认。

### M06｜体育成绩与真实性审核

- 教练员可录入训练测试成绩，按项目、成绩、单位和日期建立历史记录。
- 学生注册或更新个人最好成绩时可申报，但必须经负责教练员核验。
- 只有状态为**教练审核通过**的成绩允许作为正式最好成绩、进入排行榜。
- 拒绝的申报保留处理结果及必要审计信息，不直接覆盖历史正式成绩。
- 支持按学生、训练组、项目、日期筛选并导出`.xlsx`，教练员只能导出本人管理范围内的数据。

### M07—M10｜配套模块

- **训练反馈**：学生提交完成情况、主观用力程度及文字反馈，教练员查看。
- **消息通知**：站内公告、计划更新、审批结果；微信订阅消息能力视授权与平台条件实施。
- **数据统计**：出勤天数与比例、测试成绩趋势、组内汇总，关联Excel导出。
- **综合管理**：账号和角色、训练组管理、平台配置、数据访问审计与备份恢复机制。

### M11｜考勤与成绩排行榜

**考勤榜单**：支持月度、季度、年度及必要的自定义周期；至少显示排名、学生、有效出勤天数、出勤率、所属训练组及负责教练。支持全俱乐部及组内排行。因训练组安排可能不同，出勤率与出勤天数同时展示；请假、补签、应到天数口径由后续规则明确。

**成绩榜单**：按具体测试项目分别排行，可选择月度、季度、年度及历史最好；显示已审核成绩、学生、训练组及教练。计时项目由小到大、远度项目由大到小；按性别及适用的项目规格分榜。榜单不读取未审核的学生申报成绩。

榜单仅在俱乐部内部展示，公开范围和姓名显示策略在界面设计时明确；对未成年人坚持最小必要展示。

### M12｜竞赛报名管理（新增）

**业务目的**：让学生在小程序内完成赛事报名信息填报与必要材料上传；教练员集中核实信息、汇总参赛人员，并在赛事官方规定渠道完成正式报名，减少反复收集文件与手动整理表格。

- **赛事发布**：教练员或管理员录入比赛名称、地点、赛事时间、报名截止时间、可报项目、所需信息和材料要求，向指定训练组或俱乐部学员开放报名。
- **学生提交**：学生选择可报名赛事，查看要求，填写赛事所需参赛信息，上传必要证明资料；允许查询自己报名申请的处理进度。
- **教练员审核**：负责教练员核对报名资格、姓名与项目等信息，执行通过、退回补充或不通过，并记录审核人、时间和意见；可按赛事、项目、训练组筛选报名学生。
- **统一名单整理**：教练员按权限生成赛事报名汇总清单，支持真正的`.xlsx`导出；附件由授权教练员单独查看／下载，不在普通排名或公共页面公开。
- **正式报名状态**：严格区分“俱乐部内部审核通过”和“已向赛事主办方完成正式报名”；外部官方报名默认由教练员在线下或赛事指定平台操作，再由教练员更新进度。**第一版不承诺与赛事主办方系统自动对接或一键提交官方报名。**
- **通知与留档**：报名申请、资料退回、审核结果及正式报名结果通过站内消息提示，并保留必要操作记录；报名截止、资料退回后如何修改等规则待模块详细设计确定。

**隐私安全边界**：默认复用学生已有档案，缺少的赛事专用字段才另行采集；身份证件、证明材料等仅在赛事明确要求且合法必要时收集，限制教练员查看范围和附件下载，制定到期清理与数据留存规则，避免在日志、公开链接或榜单中暴露学生敏感信息。

## 6. 业务链路与核心状态

1. **首次加入**：微信登录 → 待激活用户 → 填写档案 → 内部审核 → 绑定训练组／教练 → 获得对应主页。
2. **计划下发**：教练员创建并发布 → 关联个人或训练组 → 学生查看 → 学生反馈 → 教练员调整。
3. **日常考勤**：训练场次建立 → 学生签到／签退 → 服务器记录 → 教练员处理异常 → 进入考勤统计与榜单。
4. **请假关联**：学生申请 → 教练员审批 → 影响相应考勤口径 → 形成可审计历史。
5. **最好成绩**：学生填写申报 → 教练员审核 → 通过则成为有效成绩 → 成绩档案／排行榜更新。
6. **竞赛报名**：教练员发布赛事 → 学生填报并上传材料 → 教练员核实与汇总 → 教练员在官方渠道报名 → 系统更新报名状态。
7. **办公导出**：教练员选择有权限的数据范围 → 后端生成Excel → 小程序内下载／打开／转发给授权办公人员。

## 7. 技术架构基准（待实际环境验证）

采用微信原生小程序（WXML／WXSS／JavaScript）＋微信云开发。前端只处理用户交互；身份、分组、审批、榜单口径及导出权限由云函数处理。数据库记录学生档案、训练计划、考勤、审批、成绩、赛事报名和审计日志。需要上传的头像及证明附件保存在受控云存储内。

**建议的逻辑数据域**：`users`、`student_profiles`、`coaches`、`training_groups`、`group_memberships`、`training_plans`、`training_sessions`、`attendance_records`、`leave_requests`、`performance_records`、`performance_reviews`、`training_feedback`、`notices`、`competitions`、`competition_registrations`、`competition_reviews`、`audit_logs`。集合名称只是技术草案，索引和字段在数据库设计阶段确定。

**关键安全约束**：云函数根据可信微信身份取得OpenID并查询数据库角色和管理范围；不得相信前端提交的`role`、`studentId`即为授权；正式业务集合原则上不允许客户端直接任意写入。Excel在服务端生成，保存期限和访问范围受控；竞赛报名附件的读取、下载与导出同样受服务端鉴权约束。所有API密钥、AppSecret和DeepSeek Key严禁提交到代码仓库。

## 8. 隐私、合规与可靠性

- 个人主体认证与备案处于审核阶段，不视为已上线；正式发布前检查服务类目、定位权限、隐私授权及小程序规则。
- 涉及学生个人信息，尤其未成年人、定位、病假材料及赛事报名附件时，遵守最小必要原则，落实告知授权、角色访问控制、数据删除和备份管理。
- 仅在学生主动签到／签退时请求位置；定位不准确或拒绝授权时提供明确提示与人工处理途径。
- 重复点击不得产生重复签到或重复成绩审核；关键审批与修改应保存操作人、时间、结果。
- 首期使用模拟数据开发；上线前进行角色越权测试、300学生容量场景的集中签到测试及Excel正确性抽查。

## 10. 第一版验收清单（不可忽略）

1. 学生、教练员和管理员的账号能通过微信身份登录，未授权用户无法进入内部数据区域。
2. 学生首次注册可填写身高、体重、体育项目、训练目标等信息，教练员可查看获授权学生档案。
3. 教练员可创建并发布训练计划，学生查看的计划与被分配的训练组一致。
4. 考勤可签到和签退，定位权限不满足时有已定义的备选流程；考勤可导出标准Excel。
5. 请假申请能完成审批并与考勤记录正确关联。
6. 学生申报最好成绩未经教练审核不能进入正式成绩和排行榜；成绩可以导出标准Excel。
7. 月、季、年考勤与分项成绩榜单可查看，均标注对应训练组与负责教练员；考勤显示有效出勤天数。
8. 学生个人主页正确展示加入俱乐部天数、个性签名及授权可见的个人数据。
9. 学生能够提交指定赛事报名信息及必要附件，教练员能够核实、退回、确认并导出报名名单；内部审核通过不能被误显示为赛事官方报名成功。
10. 服务端校验角色与管理范围，模拟越权请求被拒绝；核心数据有基本备份和日志。

- 各体育项目单位、规格、成绩相同情况下的排名规则，以及按性别分榜细则。
- 赛事创建权限、报名字段、报名截止与改报规则、附件类型及大小限制、外部正式报名状态口径。
- 云开发实际套餐、个人主体地理位置接口可用性、附件与Excel留存期限。

这些事项在进入相应模块前形成补充需求；不得由开发工具私自臆定为最终规则。
