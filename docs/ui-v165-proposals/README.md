## 二、13 项交互动效「触发 → 过程 → 结束」三态定义

全部 13 项交互均已在三套原型的业务页面与第 8 屏「动效演示页」实装并可重复点击触发，所有 CSS 动画严格仅操作 `transform` 与 `opacity`（图表使用 Canvas 2D），不触发布局重排，不滥用 `will-change`，不用 JS 逐帧修改 CSS 变量：

| 编号 | 交互项 | 触发（Trigger） | 过程（During） | 结束（End） |
| :---: | --- | --- | --- | --- |
| 01 | **页面切换（前进/后退）** | 点击页内八屏导航或业务跳转按钮 | 比较新旧屏序号区分前进/后退方向：V1 左右滑入 300ms；V2 缩放形变 320ms；V3 橙色光带扫屏 280ms | 内容停驻 `translate(0)/scale(1)`，页头角色徽章同步更新，滚回顶部 |
| 02 | **列表 Stagger 入场** | 页面切入或数据刷新完成 | 前 6 项按 34–40ms 错峰，仅执行 `translateY(10px)→0` 与 `opacity 0→1`（200ms） | 全列表稳定就位，无后续常驻动画 |
| 03 | **数字滚动 Count-up** | 进入含 PB / 出勤率 / 待办数页面或演示页点击 | `requestAnimationFrame` 三次缓出 600ms 递增，绑定 `tabular-nums` 等宽数字防横向抖动 | 精确锁定目标小数位并停止帧循环 |
| 04 | **骨架屏扫光 → 淡入** | 切换「加载」态或点击“模拟加载完成” | 橙色半透明渐变伪元素以 `transform: translateX(-100%→100%)` 扫光（1.2s/周期） | 加载完成移除骨架，真实内容 200ms 上移淡入（`jg-reveal-in`） |
| 05 | **底部弹性抽屉（下滑关）** | 点击“今日详情抽屉”或演示页 #05 | 遮罩 200ms 渐入，面板按弹性曲线 `translateY(100%→0)` 300ms 弹出；支持指针向下拖拽实时跟手 | 拖拽超过 64px 或点击遮罩/按钮后滑出隐藏并复位 `transform` |
| 06 | **表单聚焦流光 & 校验抖动** | 输入框聚焦 / 点击“校验失败抖动演示” | 底部橙色渐变光条 `scaleX(0→1)` 200ms 居中展开；空值校验时容器执行单次 `180ms` 左右 `±6px` 横抖 | 保留清晰高对比错误提示文案，抖动仅执行 1 次不循环 |
| 07 | **提交进度环 → 成功确认** | 点击“发起一次定位并签到”或“保存计划” | 按钮文字切换为品牌深色旋转进度环（`650ms/圈`）+ 处理中文案 | 核验完成切换为 400ms 弹性弹出环形 `✓` 确认，1s 后平稳复位 |
| 08 | **角色/学生局部过渡切换** | 家长端切换“林予安 / 林予宁”或演示页 #08 | 保持页头与分区按钮静止，仅对学生档案容器播放 280ms 品牌橙遮罩扫过（`jg-wipe-sweep`） | 新学生指标与环形出勤仪表平滑就位，无整页闪烁 |
| 09 | **Canvas 2D 趋势图生长** | 进入统计页、切换项目/口径或演示页 #09 | 折线与橙色渐近面积通过 `ctx.clip()` 在 320ms 内自左向右生长，延迟 120ms 后数值标签 180ms 淡入 | 正常态实线、估算不完整态虚线 + 顶部口径提示、无数据态清晰空态文案（不伪造假数） |
| 10 | **自定义下拉刷新指示器** | 点击“刷新 / 下拉刷新”或演示页 #10 | 顶部品牌橙悬浮胶囊沿 `translateY(-80px→0)` 滑出，赛道环旋转 680ms | 自动回弹隐藏并弹出轻提示，不依赖系统默认灰色菊花 |
| 11 | **空态插画淡出 → 列表滑入** | 切至「空态」后点击“插画淡出并滑入演示数据” | 空态 SVG 赛道插画与容器 180ms 缩小淡出（`opacity 0 / scale 0.94`） | 正常业务列表以 Stagger 错峰滑入 |
| 12 | **左滑审批 & 长按多选手势** | 教练待办卡片左滑（>40px）/ 点“左滑” / 长按 480ms | 前景层 `translateX(-144px)` 露出橙色“通过”与深海“退回”；长按进入批量多选高亮橙框 | 点击通过/退回后更新待办计数、标记已处理并收起滑块 |
| 13 | **方案招牌动效** | 签到成功（V1）/ 翻面按钮（V2）/ 名次置换（V3） | V1 发射三层橙光环（560ms）；V2 3D `rotateY(180deg)` 翻面（520ms）；V3 橙色光栅扫过 + FLIP 行位移动画（540ms） | 完成后全部归于静默态，同屏并发动画始终 ≤ 2 个 |

### `prefers-reduced-motion` 静态降级规范
- CSS 层在 `shared/v165-base.css` 统一声明 `@media (prefers-reduced-motion: reduce)`，将所有 `animation-duration` 与 `transition-duration` 压至 `0.01ms` 且迭代次数为 `1`。
- JS 层在 `shared/motion-charts.js` 与 `shared/v165-app-core.js` 检测 `matchMedia('(prefers-reduced-motion: reduce)').matches`：开启时，数字滚动直接渲染终值、Canvas 趋势图与环形仪表直接绘制完整终帧、FLIP 名次置换跳过位移动画直接切换新顺序，保证功能 100% 可用且零眩晕风险。

## 三、户外可读性（「日光高对比模式」）与 14 组实测对比度

- **触发方式**：三套方案顶部常驻 `44×44px`「日光模式」一键开关（且支持 `?daylight=1` 直达），完整覆盖教练工作台、考勤签到及全部 8 屏。

  - 在 390px 逻辑宽度（常见 6.1–6.7 寸手机）上，PB 字高约 `8.5mm`、环形直径约 `29mm`，符合室外田径场 1 米臂展距离下 ≥ 15 角分的快速扫视门槛。

### 明确推荐：**V3 · 光栅脉动（41 / 45）**
- **推荐理由**：① 最强烈地传达“这是一套新一代数字化训迹系统”的科技质感（蓝黑+商标橙光栅扫描与 FLIP 名次置换）；② 覆盖 36 个页面的四角色（尤其是教练审批与开发者治理）最统一，无底栏占高冲突；③ 纯 2D `transform`/`opacity` 实现，规避微信小程序 WebView 的 3D 翻面透视兼容坑。
- **选择 V3 的代价**：① 相比 V1，学生端首页缺少单手底部跳转栏（需在小程序页内合理安排顶部/首屏主入口）；② FLIP 名次置换在小程序 WXML 需通过 `wx.createSelectorQuery()` 采样前后坐标并在 WXS / `this.animate()` 中驱动，开发量略高于 V1；③ 光栅扫描仅限主动切屏或周期切换触发，严禁用于高频下拉列表防视觉疲劳。

### 三套方案各自的「不建议采用的理由」
- **不建议采用 V1（矢量竞速）的理由**：底部双排页内跳转栏占据 108px 高度，在训练计划编辑、考勤创建、赛事材料上传等表单页与系统输入法叠压明显；位移语法虽稳健但视觉惊艳度略逊于 V3。
- **不建议采用 V2（态变遥测）的理由**：招牌 3D 翻面依赖 `transform-style: preserve-3d` 与 `backface-visibility: hidden`，在部分旧款 Android 微信 XWeb 内核中存在背面穿透或闪烁风险，必须编写 2D 切换降级分支；垂直时间轴对 4+ 项待办审批队列的同屏吞吐效率不如 V3。
- **不建议采用 V3（光栅脉动）的理由**：整体视觉锋利偏硬核运动仪表风，对习惯传统浅色微信界面的家长/低龄学生初次上手存在一定适应门槛（需明显暴露「日光模式」开关）；光栅光束与 FLIP 需在小程序端借助 `this.animate()` / WXS 严格控帧。

### 替换 F1 / `jg-` 的真实代码影响（基于仓库 36 页实测盘点）
- **需改造页面数**：全部 **36/36 个已注册页面** 均引用 `jg-*` 类名与 `<jg-page-head>`，其中 **28/36 页** 引用 `<jg-empty>`；建议按 4 批灰度迁移（基础令牌+4角色首页 → 考勤/计划/统计10页 → 审批/竞赛12页 → 长尾辅助10页）。

  1. `miniprogram/app.wxss` + `miniprogram/app.json`（重写蓝黑+商标橙主令牌与日光模式 `page.is-daylight` 覆盖令牌，调整导航栏为 `#060E18` / `#EAF2FB`）。
  2. 重写 `jg-page-head`（增加日光高对比切换槽与角色状态徽章）、`jg-empty`（增加 SVG 淡出与重入过渡）、`trend-chart`（升级 Canvas 2D 左→右绘制动画、120ms 标签淡入、空态与估算虚线态）。

- **小程序端动效落地风险（不可回避）**：
  1. `setData` 驱动逐帧动画会因双线程通信掉帧 —— **数字滚动与 FLIP / 左滑手势必须通过 WXS 或原生 `this.animate()` 在渲染层执行**。

  3. 3D `preserve-3d` 翻面（若选 V2）在部分 Android 微信端存在 `backface-visibility` 失效风险，需准备 2D 交叉淡入降级。
- **后端影响**：`cloudfunctions/` 109 个 action、23 个集合、云存储 ACL 与鉴权契约 **0 改动**。

### V1.6.2 → V1.6.5 变更说明草稿（仅前端视觉 / 交互 / 动效升级）
