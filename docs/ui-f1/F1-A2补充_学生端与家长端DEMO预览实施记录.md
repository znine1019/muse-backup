## 1. 目标与思路

在**不改变真实开发者身份**的前提下，让项目所有者能在 iPhone 微信里浏览学生端与家长端的界面与交互，用于 UI 检查。

沿用既有「预览运动数据报告（DEMO）」的安全模型（`utils/demo-mode.js` + `demo/*.js` + `isDemoAllowed` 门控），新增：

- 开发者工作台两个入口：「预览学生端（DEMO）」「预览家长端（DEMO）」
- 一个演示页承载两套视角：`pages/demo/demo`
- 两层本地虚构数据：`demo/student-demo.js`、`demo/parent-demo.js`
- 统一访问守卫：`demo/demo-guard.js`

---

## 2. 为什么采用"独立演示页"而不是给各业务页加 `?demo=1`

既有报告 DEMO 的做法是把 `?demo=1` 加进 `student-report`。本轮**没有**把这个做法复制到 13 个学生页与家长页，原因：

1. 任务第八节明确要求"避免为了实现 DEMO 而在正式业务逻辑中增加大量条件分支"——给 13+ 个页面各加一条 `demoRequested && isDemoAllowed() && sessionHasRole(developer)` 分支，正是被禁止的做法。
2. 这些页面的 `onLoad` 守卫会调用真实接口并 `reLaunch`。绕过它们只能靠伪造 student/parent 会话，而任务第七条第 9 项明确禁止伪造身份绕过权限。
3. 成绩申报、请假、亲子关联属于**写入**类页面，复用真实页面会带来误写风险。

因此采用任务第四节允许的路径：**隔离的演示页面 + 复用设计系统与展示结构**。演示页只使用 `jg-` 公共类与 `jg-page-head`/`jg-empty` 组件，与正式页面同一套视觉语言，但不触碰任何业务接口。

## 3. 演示页结构

`pages/demo/demo?role=student|parent[&module=<id>][&view=catalog][&student=<n>]`

| 视图 | 触发 | 内容 |
|---|---|---|
| 工作台 | 仅 `role` | 学生/家长工作台（含演示横幅） |
| 全部功能目录 | `view=catalog` | 按业务分组的功能瓦片，点击进入子模块 |
| 模块详情 | `module=<id>` | 该模块的演示列表 / 表单 + 说明 |

- 子模块导航走**同一演示页**（`navigateTo` 新开一层），因此"返回上一级"由小程序原生返回即可。
- 底部常驻「退出演示，返回开发者工作台」→ `clearDemoState()` + `reLaunch('/pages/admin/admin')`。
- 演示数据全部在页面内存中，不写任何 storage；退出时仍调用清理钩子删除可能残留的 `demo_preview_state_v1`。

## 6. 未能完整模拟的业务及原因

| 未覆盖 | 原因 |
|---|---|
| 真实 GPS 签到定位流程 | 演示环境不获取定位，也不写入考勤；仅用"已签到/迟到/待核实"状态展示 UI |
| 成绩申报与请假审批的**真实**状态流转 | 属写入链路，演示中只做表单预览 + 本地模拟提交 |
| 真实关联凭证生成与核销 | 涉及一次性凭证与授权状态机，演示只展示"已生效/待核验"两种结果态 |
| 真实排行榜/统计的完整分页与导出 | 依赖训练组真实数据与 XLSX 导出链路，演示只展示代表性条目 |
| 训练计划编辑器的完整表单 | 表单较长且属写入，演示只展示计划列表与状态 |

以上均为**写入或依赖真实数据**的能力，符合任务第四节"无法安全复用应说明原因"的要求。

## 7. 演示数据隔离与权限检查结果

| 检查 | 结果 |
|---|---|
| 仅 develop/trial | PASS（`ALLOWED_ENV_VERSIONS = ['develop','trial']`） |
| 仅真实 developer | PASS（`sessionHasRole(session,'developer')`，停用账号同样被拒） |
| 直接以路径打开也校验 | PASS（`onLoad` → `loadDemo()` 先 `ensureSession` + `checkDemoAccess`，校验通过前不构建数据） |
| 不修改真实 roles | PASS（演示页与数据层不出现 `assignRole`/`setUserStatus`/`setGroupCoach`/`reviewRegistration`） |
| 不调用正式写入接口 | PASS（演示页**不 require `services/api`**，无 `api.*` 调用） |
| 不读取真实学生记录 | PASS（`demo/*` 无 `wx.cloud`、无 `services/api`） |
| 不产生成绩/考勤/反馈/授权记录 | PASS（数据全部本地虚构） |
| 不在正式库存储演示数据 | PASS（不写 storage、不写数据库） |
| 不伪造 student/parent 身份 | PASS（未构造任何假会话，仍以真实 developer 身份访问） |
| release 环境隐藏 + 拒绝 | PASS（工作台入口 `wx:if="{{demoAvailable}}"`，页面内二次校验） |

> 说明：前端门控只是第一道防线；正式业务数据的访问仍由云函数按可信身份判定，演示页从不访问正式数据，因此不存在绕过服务端鉴权的问题。

## 10. 真机预览操作路径

1. 微信开发者工具打开本项目 → 确认环境为开发版或体验版（release 会隐藏入口）。
2. 以**真实 developer** 账号进入「开发者工作台」。
3. 下滑到「全局管理入口」→ 点击 **「预览学生端（DEMO）」** 或 **「预览家长端（DEMO）」**。
4. 学生端：顶部黄色横幅标注 `DEMO｜虚构演示数据` → 点击任意六宫格或「全部功能」→ 进入模块详情 → 左上角返回。
5. 家长端：顶部横幅 → 用选择器切换「林越 / 苏晴」→ 点击页内跳转 chip 或「关联学生管理」→ 查看两种授权状态。
6. 任意演示页底部「退出演示，返回开发者工作台」→ 回到开发者工作台（真实角色不变）。
