## 1. 四角色体系

| 角色 | 职责 | 数据边界 |
|---|---|---|
| student | 本人训练、成绩、考勤、反馈、赛事 | 本人数据 |
| **parent（新增）** | **只读查看已授权关联学生的训练情况** | **仅 active 关联范围内的白名单字段** |
| coach | 管理负责训练组 | 本人负责训练组 |
| developer | 平台管理 | 全局 |

- 角色常量 `ROLES.PARENT = 'parent'`，已纳入 `ROLE_VALUES`，因此 `admin.assign_role` 可正常授予/撤销。
- **parent 是独立业务角色**：不复用 student 身份、不复用 coach 管理权限、不复用 developer 全局权限；权限全部由云函数判定，前端隐藏按钮不构成权限。
- developer 身份、bootstrap 状态、既有三角色行为保持不变（287 项既有测试全部通过）。

## 2. 家长注册

- 新微信号首次登录仍进入 `pending_profile`，入口页提供身份选择：**学生注册**（现有 `pages/register`）/ **家长注册**（新增 `pages/parent-register`）。
- 家长只需填写：姓名（必填）、监护人关系（父亲/母亲/其他监护人/其他）、备注（选填）。
  **不采集**运动专项、成绩、训练目标、体测数据等学生专属资料，也不采集身份证件或证件照片。
- 提交写入 `parent_profiles`（`reviewStatus=pending`），并在现有 `registration_reviews` 写入 `profileType='parent'` 的待审记录；账号状态置为 `pending_review`（已 active 的多角色账号不降级）。
- 审核在现有开发者工作台完成（`admin.list_pending_registrations` 已包含家长条目，驳回可填意见）。
- 审核通过：账号 `active` + 授予 `parent` 角色 + 写入角色绑定与审计日志；**不会自动获得任何学生的数据查看权限**。
- 审核驳回：仅当账号没有其它角色时才置为 `rejected`（避免误伤已有 coach/student 账号）；支持重新提交。
- 状态机复用现有 `USER_STATUS`：`pending_profile → pending_review → active / rejected →（重新提交）pending_review`。

## 4. 家长端安全边界（服务端强制）

家长端默认只读，服务端**不提供**任何修改类路由：不能改成绩、不能审成绩、不能建/改计划、不能改考勤、不能审批请假、不能改教练评价、不能发赛事、不能管账号、不能改训练组成员、不能读任意学生档案、不能改 developer 权限。

每次读取都依次校验：

1. 可信微信身份（`loadActiveActor`，不信任前端提交的任何 ID/角色）；
2. 账号 `status = active`；
3. 当前账号具备 `parent` 角色；
4. 存在 `parent_links` 中 `status = active` 的关联记录（家长 + 学生精确对）；
5. **该学生账号当前仍为 active**（账号停用/关联解除/角色撤销立即失去读取能力）；
6. 返回**白名单字段**，绝不返回学生完整数据库文档。

**不向家长端返回**：精确 GPS 坐标/精度/距离、非必要健康信息、私人请假原因、内部审核资料、其他学生个人资料、教练内部评价（`coachComment` 默认不返回）。

切换前端 `studentUserId` 不能越权：越权请求命中第 4/5 步直接被拒（`LINK_NOT_ACTIVE` / `STUDENT_NOT_ACTIVE`）。

## 7. 性能与资源评估（免费版 3 秒超时）

| 项 | 估算 |
|---|---|
| 家长数量 | 按 100–300 学生推算，活跃家长账号量级与家长关联量同数量级 |
| 单次请求数 | `parent.get_student_overview` 单次云函数调用内含约 10 次有界读（最大记录数均设上限） |
| 3 秒风险 | **中**：单函数内并发读较多，冷启动 + 大数据量下可能接近 3 秒 |
| 优化方案 | ① 已全部 `Promise.all` 并行 + 每项限流（计划 20、成绩 200、反馈 50、报名 20、通知 30、本月考勤）；② 建议为 `parent_links` 建组合索引；③ 若真机验证超时，拆分为 `overview` / `performance` / `attendance` 三个按需路由（仅需新增路由，不改数据结构） |
| 不引入 | 实时定位、视频、第三方推送、付费地图、AI 推理、额外外部服务器 |
