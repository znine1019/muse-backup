# 乔格训迹系统｜V1.6 微信小程序

乔格体育俱乐部内部使用的微信原生小程序。阶段1至阶段6已完成本地开发、自动化回归和云端基础验证；阶段6统计索引与新版 `api` 已部署，真实多角色统计验收统一归入阶段T。

## 当前实现

- 微信云开发初始化使用真实环境 `cloud1-d8g0egkli3191959a`。
- 云函数 `api` 负责登录、注册、审核、角色和训练组管理，按业务域拆分模块。
- 云函数 `health_check` 用于验证云函数及数据库集合连接。
- 微信一键登录，首次登录创建 `pending_profile` 账号。
- 学生首次注册、待审核、驳回后重新提交。
- 开发者安全初始化必须同时通过服务端 OpenID 白名单、一次性初始化码和事务状态校验。
- 开发者、教练员、学生三级角色，所有角色和范围由云函数重新校验。
- 开发者可管理角色、审核注册和训练组；教练员只能审核负责训练组内学生；学生只读取本人档案。
- 开发者可停用或启用账号；账号停用后即使保留原角色也不能访问内部数据。
- 训练组使用独立 `groupId` 和年份／周期字段，允许跨周期同名而不影响权限归属。
- 所有新增身份和权限操作写入审计日志。
- 学生档案扩展主项、兼项、训练年限／经历、体考目标和身高体重历史。
- 学生可提交PB成绩，成绩保持待审核状态，未审核成绩不能作为正式排行榜数据。
- 成绩项目由服务端配置单位和比较规则，计时项目越小越好，远度项目越大越好。
- 教练和开发者可按训练组范围查看学生档案；成绩审核接口已完成本地实现。
- 学生和授权教练可查看运动数据报告：身体指标趋势、approved成绩趋势、正式PB、体考目标比较和阶段变化。
- 正式PB基于完整 approved 历史计算；图表使用独立有界点数，历史读取不完整时会显式失败，不返回错误PB。
- 教练和开发者可通过成绩审核页面完成待审核成绩的通过或驳回，驳回需填写意见；并发审核不会互相覆盖。
- 教练可创建、编辑、发布、归档和复制训练计划；学生可按今日、本周和历史查看所属训练组已发布的训练计划。
- 开发者工作台在开发/预览环境提供“预览运动数据报告（DEMO）”入口，复用学生报告页与Canvas组件展示本地虚构演示数据；正式发布环境自动禁用。
- 训练计划使用单集合 `training_plans`，支持草稿/发布/归档、版本并发保护、幂等创建与复制、重要操作审计。
- 教练可在授权训练组内创建GPS考勤场次，设置签到地点、范围、时间窗口与迟到规则，查看应到、签到、迟到、请假、异常名单。
- 学生主动签到时获取一次位置，服务端计算距离并判定签到/迟到/待核实；支持请假申请、撤销与历史记录，教练审批后联动考勤。
- 阶段5本地实现赛事意向、俱乐部通知和训练反馈：学生可提交多项目参赛意向、查看通知与反馈；教练可按训练组管理赛事、发布通知、更新办理状态、评价反馈并导出真实XLSX名单。
- 赛事报名明确为内部意向收集与资料汇总，官方报名仍由教练在外部平台完成；系统不保存赛事平台密码，也不自动向第三方提交。
- 阶段5云端结构已部署：新增5个ADMINONLY集合和9个非唯一业务索引；`api` 仍为Nodejs16.13、`index.main`、256MB、3秒、无环境变量，阶段1至阶段4路由保留。
- 阶段6本地实现统计报表与排行榜：学生个人统计、正式成绩周期榜、考勤统计与出勤率榜、教练/developer统计工作台，以及成绩和考勤XLSX导出。
- 统计只使用真实业务数据；approved成绩参与正式PB和榜单，pending/rejected与DEMO数据被排除；历史成员限制会在服务端标记为估算口径。
- 阶段6云端已新增3个非唯一统计索引并部署新版 `api`：统计、排行榜、导出路由已注册；`api` 仍为Nodejs16.13、`index.main`、256MB、3秒、无环境变量。
- 阶段7（进行中）：F1 融合设计方向（A3 信息架构 + A1 竞技数据视觉 + A2 学生端体验）已完成三套候选方案对比与融合终版原型（`docs/ui-phase7/`）；阶段7-1 设计系统已落地（`app.wxss` 的 `jg-` 设计令牌与公共类 + `jg-page-head`/`jg-empty` 两个自包含组件，旧公共样式全部保留）；阶段7-2 三个工作台样板已完成（学生/教练/developer 均复用现有真实接口，逐区块加载与重试、空状态、下拉刷新、待办只跳转不写入、敏感操作保留二次确认，开发者页面统一显示开发者角色）。本轮未新增或修改任何后端接口，未部署云端，未改动其余 25 个页面。
- 阶段7-2 真机反馈修复（2026-10-13）：开发者工作台新增「查看教练工作台」入口（`navigateTo` 跳转，不授予任何额外角色，返回回到开发者工作台）；三个工作台改为 **stale-while-revalidate** —— 首次进入才显示骨架屏，返回工作台时保留已有内容并后台静默刷新（不再出现约 1 秒数据空白），支持下拉刷新保留内容、单区块失败保留上次数据并提示、展示数据更新时间、请求合并与竞态保护、身份/角色变化即失效缓存、退出登录清理缓存；新增 `scripts/check-js-syntax.js` 统一全仓库 JS 语法检查口径；未改后端、未部署云端、未创建任何领导账号。
- 阶段8（进行中）：新增家长角色（`parent`），家长工作台只读展示已授权关联学生的训练计划、已审核成绩、考勤、反馈、赛事与通知；亲子关联采用一次性凭证 + 学生确认 + 开发者核验三段授权，家长最多关联 10 名学生；新增 `parent_profiles`、`parent_links` 两个 ADMINONLY 集合与 4 个非唯一索引的设计（**尚未创建云端集合，待部署授权**）。凭证失败限流写在 `users` 上并使用原子自增。
- 阶段8第四轮：新增统一功能目录 `config/feature-catalog.js` 与四角色共用分类页 `pages/all-features/all-features`，student / coach / parent / developer 四个工作台均提供「全部功能」入口，按业务分类进入真实已注册页面；多角色账号按当前激活角色展示（`utils/active-role.js`，与 userId + 角色集合绑定，账号/角色变化与退出登录即失效）；目录只用于导航，不作权限依据，家长端目录不含任何写入入口；未新增或修改后端接口。
- 阶段8.5（微信运行前检查）：核查 profile-view 路由（已注册，后端 `admin.get_student_profile` 限 coach/developer 与训练组范围）与全仓库 33 个被引用路由，均已在 `app.json` 注册且页面文件齐全；家长端目录改为按只读能力分区定位（`/pages/parent/parent?section=...`），家长工作台新增 `scroll-into-view` 页内跳转与 `sec-*` 锚点，未新增页面或接口；新增限流并发阈值实证测试 `tests/phase8/rate-limit-race.test.js`，确认账号级与凭证级限流为“检查-再自增”的**软限制**（原子自增不丢计数，但阈值前 1 次的并发爆发会整体越阈）；本机微信开发者工具 CLI 因“服务端口”安全设置关闭而无法调用，官方编译 PENDING。未部署云端、未创建集合或索引、未改真实账号角色、未上传体验版。

## 本地检查

项目不依赖第三方 npm 包运行测试。安装 Node.js 后可执行：

```powershell
node scripts\validate-phase1.js
node scripts\wxml-lint.js
node scripts\check-js-syntax.js
node scripts\validate-phase2.js
node scripts\validate-phase3.js
node scripts\validate-phase4.js
node scripts\validate-phase5.js
node scripts\validate-phase6.js
node scripts\validate-phase7.js
node --test tests\phase1\*.test.js tests\phase2\*.test.js tests\phase3\*.test.js tests\phase4\*.test.js
node --test tests\phase5\*.test.js
node --test tests\phase6\*.test.js
node --test tests\phase7\*.test.js
node --test tests\phase8\*.test.js
```

结构校验检查环境 ID、页面结构、云函数模块拆分、服务端身份入口和常见密钥泄露问题。单元测试使用完全虚构数据。

当前阶段1至阶段8本地测试共 328 项（阶段1 50 项、阶段2 75 项、阶段3 29 项、阶段4 28 项、阶段5 47 项、阶段6 26 项、阶段7 32 项、阶段8 41 项），覆盖身份权限、成绩与报告、演示模式、训练计划、GPS签到与请假、赛事意向、通知、训练反馈、统计分析、排行榜、XLSX导出、页面路由、阶段7设计系统与三个工作台样板/“保留数据静默刷新”机制，以及阶段8家长域隔离、四角色「全部功能」功能目录与关联凭证限流并发阈值实证。结构校验：阶段1 1162 项、阶段2 121 项、阶段3 63 项、阶段4 69 项、阶段5 153 项、阶段6 73 项、阶段7 196 项，合计 1837 项。另有 `node scripts\wxml-lint.js` 全站模板结构检查与 `node scripts\check-js-syntax.js` 全仓库 JavaScript 语法检查（当前 136 个 .js 文件）。

## 安全边界

不要把 AppSecret、云函数密钥、一次性初始化码、私钥或真实学生个人信息写入代码、日志或仓库。阶段1测试必须使用模拟数据，未经确认不得部署正式环境或修改云端正式数据。
