# 乔格训迹系统｜V1.6 微信小程序

乔格体育俱乐部内部使用的微信原生小程序。阶段1至阶段6已完成本地开发、自动化回归和云端基础验证；阶段6统计索引与新版 `api` 已部署，真实多角色统计验收统一归入阶段T。

## 当前实现

- 微信云开发初始化使用真实环境 `cloud1-d8g0egkli3191959a`。
- 云函数 `api` 负责登录、注册、审核、角色和训练组管理，按业务域拆分模块。
- 云函数 `health_check` 用于验证云函数及数据库集合连接。
- 微信一键登录，首次登录创建 `pending_profile` 账号。
- 学生首次注册、待审核、驳回后重新提交。
- 开发者安全初始化必须同时通过服务端 OpenID 白名单、一次性初始化码和事务状态校验。
- 开发者、教练员、学生三级角色，所有角色和范围由云函数重新校验。
- 开发者可管理角色、审核注册和训练组；教练员只能审核负责训练组内学生；学生只读取本人档案。
- 开发者可停用或启用账号；账号停用后即使保留原角色也不能访问内部数据。
- 训练组使用独立 `groupId` 和年份／周期字段，允许跨周期同名而不影响权限归属。
- 所有新增身份和权限操作写入审计日志。
- 学生档案扩展主项、兼项、训练年限／经历、体考目标和身高体重历史。
- 学生可提交PB成绩，成绩保持待审核状态，未审核成绩不能作为正式排行榜数据。
- 成绩项目由服务端配置单位和比较规则，计时项目越小越好，远度项目越大越好。
- 教练和开发者可按训练组范围查看学生档案；成绩审核接口已完成本地实现。
- 学生和授权教练可查看运动数据报告：身体指标趋势、approved成绩趋势、正式PB、体考目标比较和阶段变化。
- 正式PB基于完整 approved 历史计算；图表使用独立有界点数，历史读取不完整时会显式失败，不返回错误PB。
- 教练和开发者可通过成绩审核页面完成待审核成绩的通过或驳回，驳回需填写意见；并发审核不会互相覆盖。
- 教练可创建、编辑、发布、归档和复制训练计划；学生可按今日、本周和历史查看所属训练组已发布的训练计划。
- 开发者工作台在开发/预览环境提供“预览运动数据报告（DEMO）”入口，复用学生报告页与Canvas组件展示本地虚构演示数据；正式发布环境自动禁用。
- 训练计划使用单集合 `training_plans`，支持草稿/发布/归档、版本并发保护、幂等创建与复制、重要操作审计。
- 教练可在授权训练组内创建GPS考勤场次，设置签到地点、范围、时间窗口与迟到规则，查看应到、签到、迟到、请假、异常名单。
- 学生主动签到时获取一次位置，服务端计算距离并判定签到/迟到/待核实；支持请假申请、撤销与历史记录，教练审批后联动考勤。
- 阶段5本地实现赛事意向、俱乐部通知和训练反馈：学生可提交多项目参赛意向、查看通知与反馈；教练可按训练组管理赛事、发布通知、更新办理状态、评价反馈并导出真实XLSX名单。
- 赛事报名明确为内部意向收集与资料汇总，官方报名仍由教练在外部平台完成；系统不保存赛事平台密码，也不自动向第三方提交。
- 阶段5云端结构已部署：新增5个ADMINONLY集合和9个非唯一业务索引；`api` 仍为Nodejs16.13、`index.main`、256MB、3秒、无环境变量，阶段1至阶段4路由保留。
- 阶段6本地实现统计报表与排行榜：学生个人统计、正式成绩周期榜、考勤统计与出勤率榜、教练/developer统计工作台，以及成绩和考勤XLSX导出。
- 统计只使用真实业务数据；approved成绩参与正式PB和榜单，pending/rejected与DEMO数据被排除；历史成员限制会在服务端标记为估算口径。
- 阶段6云端已新增3个非唯一统计索引并部署新版 `api`：统计、排行榜、导出路由已注册；`api` 仍为Nodejs16.13、`index.main`、256MB、3秒、无环境变量。

## 明确未实现

## 本地检查

项目不依赖第三方 npm 包运行测试。安装 Node.js 后可执行：

```powershell
node scripts\validate-phase1.js
node scripts\wxml-lint.js
node scripts\validate-phase2.js
node scripts\validate-phase3.js
node scripts\validate-phase4.js
node scripts\validate-phase5.js
node scripts\validate-phase6.js
node --test tests\phase1\*.test.js tests\phase2\*.test.js tests\phase3\*.test.js tests\phase4\*.test.js
node --test tests\phase5\*.test.js
node --test tests\phase6\*.test.js
```

结构校验检查环境 ID、页面结构、云函数模块拆分、服务端身份入口和常见密钥泄露问题。单元测试使用完全虚构数据。

当前阶段1至阶段6本地测试共 255 项（阶段1 50 项、阶段2 75 项、阶段3 29 项、阶段4 28 项、阶段5 47 项、阶段6 26 项），覆盖身份权限、成绩与报告、演示模式、训练计划、GPS签到与请假、赛事意向、通知、训练反馈、统计分析、排行榜、XLSX导出和页面路由。结构校验：阶段1 928 项、阶段2 120 项、阶段3 63 项、阶段4 69 项、阶段5 153 项、阶段6 73 项。另有 `node scripts\wxml-lint.js` 全站模板结构检查。

## Windows 验证

1. 使用微信开发者工具导入本目录。
2. 确认项目使用真实 AppID 和云环境 `cloud1`。
3. 运行本地结构校验和阶段1测试，确认当前代码无回归。
4. 真实coach和student账号相关流程统一按 [阶段T综合联调清单](docs/阶段T_V1.6真实微信账号综合联调清单.md) 集中执行。
5. 云端模拟账号测试涉及业务数据写入，执行前必须完成影响评估并取得确认。

## 安全边界

不要把 AppSecret、云函数密钥、一次性初始化码、私钥或真实学生个人信息写入代码、日志或仓库。阶段1测试必须使用模拟数据，未经确认不得部署正式环境或修改云端正式数据。
