reminders.complete: Mark a reminder as completed or incomplete (requires reminders)
reminders.create: Create one or more reminders on the device. ALWAYS pass `reminders_json`, a JSON array string of reminder objects, even for one reminder: [{"title":"Milk","list_name":"Shopping"}]. One call for a whole list — do NOT send a separate reminders.create per item. Each object supports: title (required), notes, due_date (Accepts an ISO 8601 timestamp, a named anchor ('now', 'today', 'yesterday', 'tomorrow'), or a SIGNED relative offset like '+1d' or '-2h'. Bare unsigned tokens like '7d' are REJECTED — always include '+' or '-'. required when any recurrence_* is set), priority (0=none default, 1=high, 5=medium, 9=low), list_id, list_name (default list if omitted), location_latitude, location_longitude, location_title, location_radius_meters (default 150), location_proximity ('arrive' default or 'leave'), and recurrence_* (Recurrence is OPTIONAL. Set recurrence_frequency to one of 'daily', 'weekly', 'monthly', 'yearly' to repeat; recurrence_interval repeats every N periods (default 1, e.g. 2 with 'weekly' = every other week). For weekly recurrence, recurrence_days_of_week is a comma-separated list of two-letter weekday codes (SU,MO,TU,WE,TH,FR,SA) — omit to repeat on the start day's weekday. Bound the series with EITHER recurrence_count (total occurrences) OR recurrence_end_date (ISO 8601, last day it can occur); supplying both returns 'invalid_argument'. Omit both for an open-ended series. a recurring reminder REQUIRES a due_date). When location fields are set on an item, ALSO call `geofence.set` with the same lat/long, radius, and trigger — the reminder alarm and the geofence are separate systems and both are needed. Response: {ok, created_count, reminder_ids, results}, where `results` carries one entry per input object in order. Entries are applied one at a time and are NOT rolled back, so a failure partway leaves the earlier ones applied — read `results` rather than `ok` alone to see which succeeded. Each successful entry is {ok: true, reminder_id, list_id, list_name}. (requires reminders)
reminders.delete: Delete a reminder from the device (requires reminders)
reminders.list: List reminders from the device, optionally filtered by list and completion status. Location-based reminders include location trigger details in the response. Recurring reminders include a `recurrence` object {frequency, interval, days_of_week?, end_date?, occurrence_count?} in the response. `due_date`, `start_date` and `completion_date` (the response fields, not the `start_date`/`end_date` filter arguments) are UTC ISO-8601 and are NOT converted for you. Read them against the user's time zone — the `client_timezone` on their message, which follows them when they travel — before stating a time, and never take the day, date, or weekday straight off them: near either end of the day the UTC date falls on a different day from the user's, in whichever direction their offset runs. A reminder saved with no time of day is indistinguishable here from one due at midnight, so do not assert a time for one that lands on midnight local. A `recurrence` object's own `end_date` is UTC on the same terms — convert it before stating when the series stops. Date arguments accept either an ISO 8601 timestamp (e.g. '2025-04-24T00:00:00Z') OR a named anchor ('now', 'today', 'yesterday', 'tomorrow') OR a SIGNED relative offset ('-7d', '+7d', '-24h', '+30m', '-1h'). Bare unsigned tokens like '7d' or '24h' are REJECTED with error 'invalid_argument' because they don't say past vs. future — always include '+' or '-'. start_date MUST be earlier than end_date; inverted ranges return 'invalid_argument' with the parsed timestamps so you can fix the call. (requires reminders)
reminders.update: Update an existing reminder on the device. Pass reminder_id (from reminders.list) plus only the fields to change; omitted fields are left unchanged. Recurrence is OPTIONAL. Set recurrence_frequency to one of 'daily', 'weekly', 'monthly', 'yearly' to repeat; recurrence_interval repeats every N periods (default 1, e.g. 2 with 'weekly' = every other week). For weekly recurrence, recurrence_days_of_week is a comma-separated list of two-letter weekday codes (SU,MO,TU,WE,TH,FR,SA) — omit to repeat on the start day's weekday. Bound the series with EITHER recurrence_count (total occurrences) OR recurrence_end_date (ISO 8601, last day it can occur); supplying both returns 'invalid_argument'. Omit both for an open-ended series. Pass recurrence_frequency: 'none' to remove recurrence. Setting or keeping recurrence REQUIRES a due_date (set one here or already on the reminder). Response (success): {ok: true, reminder_id, list_id, list_name}. (requires reminders)
